# OptiTrack × JNCRadio VNA 3G リアルタイム同期計測システム

メアンダコイル服（ウェアラブルアンテナ／コイル）の**3次元位置**と**高周波特性（S11・インピーダンス）**を、同一 Windows PC 上で同時かつ同期的に取得し、機械学習・解析用の CSV データセットとして保存するための Python アプリケーションです。

位置トラッキングは腕に取り付けた **3 個の対象**（**上腕 / 関節 / 前腕**）を対象とします。**Motive 側で各対象に付けた「名前」（`upperarm` / `joint` / `forearm`）をキーに、実行ごとに変わる ID を起動時に自動解決**します（後述「動的マッピング」）。OptiTrack の光学式モーションキャプチャ（Motive）から得られるこの 3 対象の座標と、JNCRadio VNA 3G から得られる反射係数 S11 を、マルチスレッドかつスレッドセーフに結合し、以下の形式で記録します。

```
[Timestamp,
 UpperArm_X, UpperArm_Y, UpperArm_Z,
 Joint_X,    Joint_Y,    Joint_Z,
 Forearm_X,  Forearm_Y,  Forearm_Z,
 S11_Real, S11_Imag, Z_R, Z_X]
```

> **【重要】ID ではなく名前で識別します。**
> Motive はセッションごとに対象の ID（Streaming ID / マーカー ID）を自動採番するため、**実行のたびに ID が変動**します。本システムはこの問題を避けるため、ID を直接指定するのではなく、Motive 側で設定された**名前**をキーにして、起動時に配信される **Data Descriptions（データ記述）** から現在の ID／インデックスを**動的に解決**します。一度名前を合わせておけば、以後は ID が変わっても設定変更は不要です。

## 1. システム構成・動作環境

### 1.1 概要

本システムは、**1 台の Windows PC（ThinkPad）内で完結する**ことを最大の特徴とします。モーションキャプチャ用の PC と計測用の PC を分離せず、Motive・Python スクリプト・VNA 制御のすべてを同一マシン上で動作させることで、ネットワーク遅延や時刻同期のずれを最小化し、配線をシンプルに保ちます。

```
┌──────────────────────────────────────────────────────────────┐
│                  Windows PC (ThinkPad)                        │
│                                                              │
│   ┌────────────────┐         NatNet (UDP)                    │
│   │  Motive        │  ───────────────────────────┐           │
│   │  (OptiTrack)   │   127.0.0.1 (loopback)       │           │
│   └────────────────┘                              ▼           │
│         ▲                            ┌──────────────────────┐ │
│         │ 光学トラッキング            │  Python 同期計測       │ │
│         │                            │  スクリプト            │ │
│   （カメラ群）                        │  ・NatNetClient (受信) │ │
│                                      │  ・名前→ID 動的解決    │ │
│                                      │  ・pyserial (VNA制御)  │ │
│   ┌────────────────┐   USB           │  ・threading.Lock      │ │
│   │ JNCRadio VNA 3G│ ◀──(COMポート)──▶│  で同期               │ │
│   │  PORT1 = S11   │   115200 bps     └──────────┬───────────┘ │
│   └────────────────┘                            │             │
│         ▲                                        ▼             │
│   （メアンダコイル服 = DUT）              sync_dataset.csv       │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 必要なハードウェア

| 機器 | 役割 | 備考 |
|------|------|------|
| **Windows PC（ThinkPad）** | Motive と Python スクリプトを同時実行する計測ホスト | 後述の通り高負荷になるため、できる限り高性能な機体を推奨 |
| **OptiTrack システム（カメラ群 + Motive）** | 腕に取り付けた 3 個の対象の 3 次元位置をリアルタイム取得 | Motive のライセンスおよびキャリブレーション済みのキャプチャ空間が必要 |
| **JNCRadio VNA 3G** | 単一周波数における S11（反射係数）を測定 | USB Type-C ケーブルで PC に接続。シリアル（仮想 COM ポート）として認識される |
| **メアンダコイル服（DUT）** | 被測定物 | VNA の **PORT1** に接続。上腕・関節・前腕に各 1 個、計 3 個の反射マーカーを貼付 |

### 1.3 ソフトウェア動作環境

- **OS:** Windows 10 / 11
- **Python:** 3.8 以上（64bit 推奨）
- **Motive:** OptiTrack 純正ソフトウェア（Data Streaming 対応バージョン。NatNet 4.x / Motive 3.1 系で動作確認）
- **NatNet SDK:** OptiTrack 公式 SDK（`NatNetClient.py` を使用）

## 2. セットアップ（環境構築）

### 2.1 Python ライブラリのインストール

コマンドプロンプト（または PowerShell）で以下を実行してください。

```bash
pip install pyserial pandas numpy
```

| ライブラリ | 用途 |
|-----------|------|
| `pyserial` | JNCRadio VNA 3G とのシリアル（COM ポート）通信 |
| `pandas` | 取得後のデータセットの読み込み・解析（後処理用、計測本体には任意） |
| `numpy` | 数値計算・複素数演算の補助（任意） |

> **補足:** 計測スクリプト本体の動作に必須なのは `pyserial` のみです。`pandas` / `numpy` は取得済み CSV の解析・可視化で利用するためのものです。

### 2.2 `NatNetClient.py` の配置（重要）

OptiTrack との通信には、OptiTrack が公式に配布する **NatNet SDK 同梱の Python サンプル `NatNetClient.py`** を使用します。これは `pip` では入手できません。本スクリプトは以下の **2 箇所のいずれか**に SDK ファイルがあれば自動で読み込みます（`sys.path` に自動追加）。

- **(A) 同梱 SDK をそのまま使う場合:** リポジトリ内の `./NatNetSDK/Samples/PythonClient/` に `NatNetClient.py` 等が置かれていれば、追加作業は不要です。
- **(B) 手動配置する場合:** OptiTrack 公式サイト（または Motive インストールフォルダ）から **NatNet SDK** を入手し、以下のファイルを **本体スクリプトと同じフォルダ**にコピーします。
  - `NatNetClient.py`（必須）
  - `MoCapData.py`（**必須**。フレームデータ（Rigid Body / Marker Set / Labeled Marker）の構造を解釈するために使用します）
  - `DataDescriptions.py`（**必須**。`NatNetClient.py` が内部で import し、**名前→ID の動的解決にも使用します**）

想定するフォルダ構成は以下のいずれかです。

```
# (A) 同梱 SDK 構成（このリポジトリの構成）
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── README.md
└── NatNetSDK/
    └── Samples/
        └── PythonClient/
            ├── NatNetClient.py
            ├── MoCapData.py
            └── DataDescriptions.py

# (B) 手動配置構成
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── NatNetClient.py
├── MoCapData.py
├── DataDescriptions.py
└── README.md
```

> **対応バージョン:** 本スクリプトは **NatNet 4.x（Motive 3.1 系）** の `NatNetClient.py` に合わせて実装しています。フレーム受信には `new_frame_with_data_listener`（`data_dict["mocap_data"]` に `MoCapData` を渡す）を使用します。名前解決には、サーバへ **Data Descriptions（`NAT_REQUEST_MODELDEF`）** を要求して得られる記述を利用します。

## 3. 事前設定の手順

計測を開始する前に、Motive 側と JNCRadio VNA 3G 側の双方で設定を済ませておく必要があります。

### 3.1 Motive（OptiTrack）側の設定

Motive を起動し、キャプチャ空間のキャリブレーションを済ませたうえで、まず **計測対象 3 個に分かりやすい「名前」を付け**、続いて **Data Streaming** パネルを設定します。

#### (a) 3 個の対象への「名前」の割り当て【最重要】

本システムは **ID ではなく名前で対象を識別**します。Motive 側で以下を行ってください。

1. 上腕・関節・前腕のそれぞれに反射マーカーを **1 個ずつ（計 3 個）** 取り付けます。
2. Motive 上で各対象に **名前を付けます**。スクリプト既定では次の名前を使います（**大文字・小文字、前後の空白は無視**して照合します）。

   | 部位 | Motive 上で付ける名前（既定） |
   |------|------------------------------|
   | 上腕 | `upperarm` |
   | 関節 | `joint` |
   | 前腕 | `forearm` |

3. 名前の付け方は、Motive 上での扱い方に応じて **どちらでも構いません**（本スクリプトは自動判別します）。
   - **(i) リジッドボディ（Rigid Body）として扱う場合:** 各マーカー（または剛体）に名前（例 `upperarm`）を付けます。→ Rigid Body の記述から `名前→現在の RigidBody ID` を解決します。
   - **(ii) マーカーセット（Marker Set）内の単一マーカーとして扱う場合:** マーカーセット内の各マーカーに名前（例 `upperarm`）を付けます。→ Marker Set の記述から `名前→（セット名・インデックス）` を解決します。

> **ID を控える必要はありません。** 旧バージョンのように `UPPER_ARM_ID` 等へ ID を手入力する作業は不要になりました。**名前さえ一致していれば、実行ごとに ID が変わっても自動で追従**します。

> **ヒント（名前が分からないとき）:** スクリプト冒頭の `DEBUG_PRINT_DESCRIPTIONS = True`（既定で有効）にしておくと、起動時に Motive から受信した **Rigid Body 名の一覧**と **Marker Set 内のマーカー名の一覧**がコンソールに出力されます。Motive 側の正確な名前を確認し、スクリプトの `TARGET_NAMES` に合わせてください。

#### (b) Data Streaming の設定

1. メニューから **Data Streaming** パネルを開きます。
2. **Broadcast Frame Data** を **ON（有効）** にします。
3. **Local Interface** を **`127.0.0.1`（localhost / loopback）** に設定します。
   - 同一 PC 内でデータを受け渡すため、外部ネットワークではなくループバックアドレスを指定するのが要点です。
4. **Transmission Type** を **Unicast** に設定します。
   - 同一 PC 内のループバック通信では Multicast よりも Unicast の方が安定します。本スクリプトも Unicast 前提（`set_use_multicast(False)`）で実装されています。
5. 対象の扱い方に応じて、配信を **ON** にします。
   - リジッドボディとして扱う場合: **Rigid Bodies** を ON。
   - マーカーセット内マーカーとして扱う場合: **Markers**（Labeled Markers）を ON。
   - これらが無効だと座標が配信されず、名前を解決できても座標が空欄になります。

> **補足:** 名前→ID の解決には Motive からの **Data Descriptions（モデル定義）** が必要です。本スクリプトは起動時に `NAT_REQUEST_MODELDEF` を送ってこれを明示的に要求します。Data Streaming が有効であれば、特別な追加設定なしに応答が得られます。

### 3.2 JNCRadio VNA 3G 側の設定

#### (a) COM ポート番号の確認

1. USB Type-C ケーブルで JNCRadio VNA 3G を PC に接続します。
2. **デバイスマネージャー** を開きます（`Win + X` → 「デバイス マネージャー」）。
3. **「ポート (COM と LPT)」** の項目を展開します。
4. 接続した VNA に対応する仮想シリアルポート（例: `USB Serial Device (COM3)`）を確認し、**COM 番号**を控えます。
   - 接続前後でデバイスマネージャーを見比べると、新たに増えたポートが VNA に対応するものです。
   - この COM 番号を後述の `NANOVNA_PORT` に設定します。

> JNCRadio VNA 3G のシリアルボーレートは適応式ですが、本体・スクリプトともに **115200 bps** を使用します（マニュアル §7 準拠）。

#### (b) キャリブレーション（SOLT）の事前実施【強く推奨】

S11 を正確に測定するため、**計測を開始する前に本体側で校正（キャリブレーション）を済ませておくこと**を強く推奨します。

1. メアンダコイル服を接続する **PORT1（S11 測定ポート）** に対して、付属の校正キットを用いて **SOLT 校正** を行います。
   - **S** = Short（短絡）
   - **O** = Open（開放）
   - **L** = Load（50 Ω 終端負荷）
   - **T** = Through（PORT1–PORT2 間。S11 のみであれば省略可）
2. マニュアル §4.4 / §7.2.14（`cal` コマンド）の手順に従い、各標準器を接続して校正を実施します。校正後は必ず校正データを保存（`save {id}` または本体メニュー）してください。
3. 測定したい単一周波数（例: 13.56 MHz）を含む周波数範囲で校正されていることを確認します。

> **重要:** 未校正のまま測定すると S11 が不正確になり、後段で算出されるインピーダンス Z も信頼できない値になります。データセットの品質を担保するため、校正は必ず実施してください。

## 4. 使い方（実行手順）

### 4.1 スクリプト内変数の書き換え

`sync_optitrack_nanovna.py` の冒頭にある **設定ブロック**を、ご自身の環境に合わせて編集します。

```python
# --- NanoVNA / JNCRadio VNA-3G (シリアル) ---
NANOVNA_PORT   = "COM3"        # ← デバイスマネージャーで確認した COM 番号に変更
NANOVNA_BAUD   = 115200        # ボーレート（通常は変更不要）
TARGET_FREQ_HZ = 13_560_000    # ← 測定したい単一周波数 [Hz]（例: 13.56 MHz）
SCAN_POINTS    = 11            # 1回の掃引点数（本機の最小は 11。同一周波数で平均）
Z0             = 50.0          # 特性インピーダンス [Ω]（通常は 50）

# --- OptiTrack (NatNet) ---
NATNET_SERVER_IP = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_LOCAL_IP  = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_USE_MULTICAST = False    # 同一PCループバックは Unicast 推奨（通常は変更不要）

# 計測対象を「Motive 側で付けた名前」で指定する（★ID はハードコードしない★）。
# 左 = スクリプト内部の論理名（CSV 列名に対応）, 右 = Motive 上の名前（大小・空白は無視）。
TARGET_NAMES = {
    "UpperArm": "upperarm",   # ← 上腕   の Motive 上の名前
    "Joint":    "joint",      # ← 関節   の Motive 上の名前
    "Forearm":  "forearm",    # ← 前腕   の Motive 上の名前
}

# True にすると、受信した Data Descriptions の名前一覧を出力（名前調査用）
DEBUG_PRINT_DESCRIPTIONS = True
# 名前解決（Data Descriptions 受信）を待つ最大秒数
DESC_RESOLVE_TIMEOUT_SEC = 5.0

SKIP_OCCLUDED = True            # 隠れ（オクルージョン）中・トラッキング無効中は更新をスキップ

# --- 出力 ---
OUTPUT_CSV = "sync_dataset.csv" # 出力 CSV ファイル名（任意で変更可）
```

最低限、以下を環境に合わせて変更してください。

| 変数 | 設定内容 |
|------|---------|
| `NANOVNA_PORT` | デバイスマネージャーで確認した COM 番号（例: `"COM5"`） |
| `TARGET_FREQ_HZ` | 測定対象の単一周波数（Hz 単位の整数。`13_560_000` = 13.56 MHz） |
| `TARGET_NAMES` | 各部位に対応する **Motive 上の名前**。Motive 側の名前と綴りが一致していれば OK（大小・前後空白は無視） |

> **注意:** `TARGET_NAMES` の右側（Motive 上の名前）が、Motive で実際に付けた名前と一致している必要があります。一致しない部位は「未解決」となり、その列が空欄になります。名前が不明な場合は `DEBUG_PRINT_DESCRIPTIONS = True`（既定）のまま実行し、起動時に出力される名前一覧を確認してください。

### 4.2 実行

Motive を起動して Data Streaming を有効化し、VNA を USB 接続した状態で、以下を実行します。

```bash
python sync_optitrack_nanovna.py
```

正常に起動すると、コンソールに接続状況・名前解決の結果・計測ログが表示されます。

```

[DESC] Rigid Bodies: upperarm(id=3), joint(id=4), forearm(id=5)
[INFO] UpperArm -> Rigid Body (現在ID=3)
[INFO] Joint    -> Rigid Body (現在ID=4)
[INFO] Forearm  -> Rigid Body (現在ID=5)
[INFO] 計測対象(Motive名 -> 解決結果):
       UpperArm ('upperarm') -> RigidBody id=3
       Joint    ('joint')    -> RigidBody id=4
       Forearm  ('forearm')  -> RigidBody id=5

```

> **ポイント:** `[INFO] ... -> RigidBody id=3` のように、**実行ごとに変わる ID が名前から自動解決**されていることが分かります。次回 ID が `id=7` などに変わっても、設定変更なしでそのまま動作します。
> ログの `UA` / `J` / `FA` はそれぞれ 上腕（UpperArm）/ 関節（Joint）/ 前腕（Forearm）の現在座標 (X, Y, Z) を示します。

### 4.3 終了方法

計測を終了するには、コンソール上で **`Ctrl + C`** を押します。

本スクリプトは `Ctrl + C` を検出すると、以下を**安全に**実行します。

1. 計測ループを停止する。
2. VNA に `resume` を送って掃引表示を元に戻し、シリアルポートを閉じる。
3. NatNet クライアントをシャットダウンする。
4. これまでに取得したサンプル数を表示する。

なお、CSV は計測中に **1 行ごとに逐次フラッシュ（`f.flush()`）して保存**しているため、万一プログラムが途中で異常終了しても、それまでのデータは失われません。

## 5. 出力データ構造（CSV ヘッダー解説）

出力ファイル（既定: `sync_dataset.csv`）は、以下の 14 カラムを持つ CSV です。位置データは **上腕・関節・前腕の 3 個 × (X, Y, Z) = 9 値**が含まれます。各座標は、対応する対象の中心座標（**Motive 3.x 標準の Z-Up 座標系**、単位はメートル）です。

> **座標系について:** 本システムは Motive で設定された配信座標系の値をそのまま記録します。Motive 3.x 標準の **Z-Up** 設定では、おおむね Z 軸が鉛直上向き、X–Y が水平面となります。解析時は Motive 側の座標系設定に合わせて軸の向きを解釈してください。

| カラム名 | 意味 | 単位 |
|----------|------|------|
| `Timestamp` | 各サンプルを記録した PC のローカル時刻（ISO 8601 形式、ミリ秒精度） | — |
| `UpperArm_X` | **上腕**の中心 X 座標（Motive 座標系） | メートル [m] |
| `UpperArm_Y` | **上腕**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `UpperArm_Z` | **上腕**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `Joint_X` | **関節**の中心 X 座標（Motive 座標系） | メートル [m] |
| `Joint_Y` | **関節**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `Joint_Z` | **関節**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `Forearm_X` | **前腕**の中心 X 座標（Motive 座標系） | メートル [m] |
| `Forearm_Y` | **前腕**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `Forearm_Z` | **前腕**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `S11_Real` | 反射係数 S11 の**実部** | 無次元（線形） |
| `S11_Imag` | 反射係数 S11 の**虚部** | 無次元（線形） |
| `Z_R` | 複素インピーダンス Z の**実部（抵抗 R）** | オーム [Ω] |
| `Z_X` | 複素インピーダンス Z の**虚部（リアクタンス X）** | オーム [Ω] |

> ある対象がトラッキングロスト等で未受信の場合、その対象の X/Y/Z セルは空欄になります。上腕と前腕の位置関係から、腕の曲げ角度を後処理で算出できます。

### 5.1 同期の仕組み

OptiTrack の更新レート（数百 Hz）と VNA の取得レート（1 点あたり数十〜数百 ms）には大きな差があります。本システムでは、フレームが届くたびにコールバックが **起動時に解決した名前→ID／インデックスのマッピング**を使って 3 対象の座標を `threading.Lock()` 下で「対象ごとの最新座標」として更新し続けます。そして **VNA の S11 を 1 点取得し終えた「その瞬間」に、上腕・関節・前腕 3 対象の最新座標を同一ロック下で一括スナップショット**して結合します。すなわち CSV の 1 行は、「ある S11 測定」と「その測定完了時点で最も新しい 3 対象（計 9 値）の位置データ」をまとめたものです。

ロックは 3 対象まとめて取得する間だけ保持されるため、読み出しの途中で一部の対象だけが更新される（行内で対象ごとに時刻がずれる）ことはありません。

### 5.2 インピーダンスへの変換

CSV に記録される `Z_R`・`Z_X` は、VNA から得られた**生の S11（複素数）**を、特性インピーダンス **Z₀ = 50 Ω** を用いて以下の標準的な公式で換算したものです。

```
Z = Z0 × (1 + S11) / (1 − S11)
```

ここで、

- `S11 = S11_Real + j·S11_Imag`（反射係数、複素数）
- `Z = Z_R + j·Z_X`（負荷インピーダンス、複素数）
- `Z_R`（= R）が抵抗成分、`Z_X`（= X）がリアクタンス成分

を表します。生の S11 と換算後の Z の双方を保存しているため、後処理で別の Z₀ を用いた再計算や、S11 ベースの解析（リターンロス・VSWR 等）も柔軟に行えます。

## 6. 動的マッピングの仕組み（技術解説）

実行ごとに変わる ID を直接扱う代わりに、**Motive 側の名前を起点に ID／インデックスを自動解決**します。処理の流れは次の通りです。

1. **Data Descriptions の要求と捕捉（起動時に 1 回）**
   起動時に `NAT_REQUEST_MODELDEF` をサーバ（Motive）へ送り、**Data Descriptions（モデル定義）** を受信します。
   同梱の `NatNetClient.py` は受信した記述を内部で表示するだけで保持しないため、本スクリプトは **SDK ファイルを改変せず**、記述を解析する内部メソッドを実行時にラップして解析結果を横取りします（`_install_description_capture()`）。

2. **名前→ID／インデックスの解決（`resolve_targets_from_descriptions()`）**
   受信した記述から、`TARGET_NAMES` の各名前を次のいずれかとして解決します（前者を優先）。
   - **Rigid Body** の名前と一致 → `{"kind": "rigid_body", "id": <現在の RigidBody ID>}`
   - **Marker Set** 内のマーカー名と一致 → `{"kind": "marker_set", "set": <セット名>, "index": <マーカー番号>}`
   名前の比較は前後空白の除去と小文字化で正規化して行います。

3. **毎フレームの座標抽出**
   フレーム受信コールバックでは、解決済みマッピングを使って座標を取り出します。
   - rigid_body エントリ → そのフレームの Rigid Body 群から **ID 一致**の `pos` を取得。
   - marker_set エントリ → そのフレームの Marker Set 群から **セット名＋インデックス一致**の座標を取得。
   `SKIP_OCCLUDED = True` のときは、トラッキング無効（Rigid Body の `tracking_valid` が False）の間は更新せず、直前の有効値を保持します。

この設計により、**実行ごとに ID が変動しても、名前さえ一致していれば再設定なしで正しく紐付け**できます。なお解決は起動時の 1 回スナップショットです。計測中に Motive 側で対象を作り直した場合は、スクリプトを再起動して再解決してください。

## 7. 注意事項・トラブルシューティング

### 7.1 名前が解決できない / OptiTrack のデータが受信できない場合

起動時に `[WARN] '...' を Data Descriptions 内に発見できませんでした` や `[WARN] N秒以内に Data Descriptions を取得できませんでした`、または座標カラムが空欄になる場合は、以下を確認してください。

- **`TARGET_NAMES` の名前が Motive 側と一致しているか。** これが最も多い原因です。`DEBUG_PRINT_DESCRIPTIONS = True`（既定）で起動し、`[DESC] Rigid Bodies: ...` / `[DESC] Marker Set マーカー名: ...` に出力される**実際の名前**と綴りを突き合わせてください（大小・前後空白は無視されます）。
- **Motive の Data Streaming が ON になっているか。** `Broadcast Frame Data` が有効である必要があります。
- **対象の種類に応じた配信が ON になっているか。** リジッドボディなら **Rigid Bodies**、マーカーセット内マーカーなら **Markers（Labeled Markers）** を ON にしてください。これが無効だと、名前は解決できても座標が配信されません。
- **Local Interface が `127.0.0.1`（localhost）になっているか。** 別の NIC（有線/無線 LAN の IP）が選択されていると、ループバックでは受信できません。
- **Transmission Type が Unicast になっているか。** 本スクリプトは Unicast 前提です。Multicast にしている場合はスクリプト側を `NATNET_USE_MULTICAST = True` に変更してください。
- **一部の対象だけ空欄になる場合。** その対象の名前だけが未解決か、トラッキングロスト（オクルージョン等）の可能性があります。起動時の `[INFO] 計測対象(Motive名 -> 解決結果)` のログで、その部位が「未解決」になっていないか確認してください。
- **計測中に `[WARN] OptiTrack フレームが N.Ns 途絶しています` が出る場合。** Motive のストリーミングが一時停止・切断された可能性があります（§7.3 参照）。
- **Windows ファイアウォール。** ループバック通信は通常ブロックされませんが、セキュリティソフトが UDP 通信を遮断している場合は、Python（`python.exe`）の通信を許可してください。
- **`NatNetClient.py` / `MoCapData.py` / `DataDescriptions.py` が読み込めるか。** これらが見つからないと import に失敗し、OptiTrack なしで続行されて座標は空欄になります。同梱の `./NatNetSDK/Samples/PythonClient/` か、本体スクリプトと同じフォルダに配置してください。

### 7.2 COM ポートが開けない場合

`[ERROR] VNA シリアル接続に失敗` と表示される場合は、以下を確認してください。

- **COM 番号が正しいか。** デバイスマネージャーで再確認してください。USB を挿し直すと番号が変わることがあります。
- **他のソフトがポートを占有していないか。** **nanovna-saver や JNCRadio 純正 PC ソフト、シリアルターミナル（PuTTY 等）** が同じ COM ポートを開いていると、Python からはアクセスできません。**それらのソフトを必ず閉じてから**実行してください。
- **VNA の電源が入っているか／ケーブルがデータ通信対応か。** 充電専用ケーブルではシリアルが認識されません。
- **ドライバ。** ポートが現れない場合は USB シリアルドライバの再インストールを検討してください。

### 7.3 高負荷時のデータドロップ対策（重要）

同一 PC 上で **Motive（リアルタイム 3D 描画）** と **Python 計測スクリプト**を同時に高負荷で動作させるため、CPU/GPU リソースの競合により OptiTrack のフレーム取りこぼし（ドロップ）が発生することがあります。これを防ぐための実践的なテクニックを示します。

- **計測中は Motive のウィンドウを最小化する。** Motive の 3D ビューポートの描画は GPU/CPU を大きく消費します。Data Streaming（データ配信）自体はウィンドウを最小化しても継続されるため、**計測開始後は Motive を最小化して描画負荷を下げる**ことで、ドロップを大幅に削減できます。
- **不要なアプリケーションを終了する。** ブラウザや他の重いアプリを閉じ、リソースを計測に集中させます。
- **電源プランを「高パフォーマンス」に設定する。** ThinkPad の省電力設定によるクロック低下を防ぎます。可能であれば AC 電源に接続してください。
- **Motive の描画設定を軽くする。** 描画レート（Viewport の更新頻度）やトレイル表示などを抑えると、さらに負荷を下げられます。
- **掃引点数を見直す。** `SCAN_POINTS` を必要以上に大きくすると VNA の 1 点取得時間が延び、全体のスループットが低下します。単一周波数の平均が目的であれば、本機の最小値である `11` で十分です。
