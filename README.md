# OptiTrack × JNCRadio VNA 3G リアルタイム同期計測システム

メアンダコイル服（ウェアラブルアンテナ／コイル）の**3次元位置**と**高周波特性（S11・インピーダンス）**を、同一 Windows PC 上で同時かつ同期的に取得し、機械学習・解析用の CSV データセットとして保存するための Python アプリケーションです。

位置トラッキングは腕に取り付けた **3 個の対象**（**上腕 / 関節 / 前腕**）を対象とします。**Motive 側で名前付けや ID 設定をしなくても、計測開始時の「高さ」から 3 対象を自動的に判別・マッピング**します（後述「自動判別の仕組み」）。VNA は **12.5–14.5 MHz を 101 点で掃引**し、毎フレーム 101 点分の S11 を取得して `scikit-rf` でインピーダンス **Z11** に変換します。OptiTrack の 3 対象の座標とこの掃引データをマルチスレッドかつスレッドセーフに結合し、**1 行に「位置情報 ＋ 101 点分の各周波数の S11/Z」を並べた**以下の形式で記録します。

```
[Timestamp,
 UpperArm_X, UpperArm_Y, UpperArm_Z,
 Joint_X,    Joint_Y,    Joint_Z,
 Forearm_X,  Forearm_Y,  Forearm_Z,
 S11_Real_12.5, S11_Imag_12.5, Z_R_12.5, Z_X_12.5,
 ... (各掃引周波数ごとに 4 列) ...,
 S11_Real_14.5, S11_Imag_14.5, Z_R_14.5, Z_X_14.5]
```

計測中は GUI 上に **周波数 vs インピーダンス（Z_R / Z_X）のリアルタイムグラフ**が表示され、腕を動かすと整合のずれ（共振点の移動）が視覚的に確認できます。

> **【重要】ID は「開始時の高さ」で自動判別します。**
> Motive はセッションごとに対象の ID（Streaming ID / マーカー ID）を自動採番するため、**実行のたびに ID が変動**します。本システムはこの問題を避けるため、ID を直接指定したり名前を設定したりせず、**計測開始時の最初の有効フレームで 3 対象の高さを比較**して、
> - 一番高い位置 → **upperarm（上腕）**
> - 中間の位置 → **joint（関節）**
> - 一番低い位置 → **forearm（前腕）**
>
> と自動的に ID を確定します。一度確定した ID は計測終了まで固定され、毎フレームの座標取得に使われます。

> **【操作方法】GUI（tkinter）で計測します。**
> プログラムを実行すると操作画面が立ち上がります。**COM ポートを選択 → ［計測開始］→ ［計測終了 / 保存］** の流れで操作し、終了時にファイル保存ダイアログで保存先を指定します。計測・通信はバックグラウンドスレッドで動くため GUI は固まりません。終了時（終了ボタン／ウィンドウ×／プロセス終了のいずれでも）に、**VNA のクローズ・NatNet の切断・全スレッドの join を必ず実行**してリソース（COM ポート・UDP ソケット）を確実に解放します。これにより「2 回目以降の起動でフリーズする」問題を防ぎます。
>
> 計測する S パラメータは **S11 固定**です。

> **【VNA 接続：COM ポートの動的選択】画面で接続先 COM ポートを選べます。**
> GUI の「COM Port」ドロップダウンが、PC が認識しているシリアルポートを自動でリストアップします。VNA を後から挿した場合は **［ポート再検索］** ボタンで一覧を更新できます（再起動不要）。［計測開始］時に選択された COM ポートが開けない（存在しない／他ソフトが占有）場合は、**クラッシュせず警告ポップアップ**（`messagebox.showerror`）を表示し、再選択して再開できます。

> **【VNAなしテストモード】VNA 実機が無くても OptiTrack 単体で動作確認できます。**
> COM ポートの一覧末尾にある **「None（VNAなしテストモード）」** を選んで［計測開始］すると、**VNA の接続・初期化を完全にスキップ**（接続エラーも出さない）し、OptiTrack の座標（UpperArm / Joint / Forearm）だけをリアルタイム取得します。VNA 由来のカラム（`S11_Real, S11_Imag, Z_R, Z_X`）には **ダミー値 0** が入ります。終了・CSV 保存の流れは通常モードと同一です。OptiTrack 受信や保存ロジックの確認に使えます。

## 1. システム構成・動作環境

### 1.1 概要

本システムは、**1 台の Windows PC（ThinkPad）内で完結する**ことを最大の特徴とします。モーションキャプチャ用の PC と計測用の PC を分離せず、Motive・Python スクリプト・VNA 制御のすべてを同一マシン上で動作させることで、ネットワーク遅延や時刻同期のずれを最小化し、配線をシンプルに保ちます。

```
┌──────────────────────────────────────────────────────────────┐
│                  Windows PC (ThinkPad)                        │
│                                                              │
│   ┌────────────────┐         NatNet (UDP)                    │
│   │  Motive        │  ───────────────────────────┐           │
│   │  (OptiTrack)   │   127.0.0.1 (loopback)       │           │
│   └────────────────┘                              ▼           │
│         ▲                            ┌──────────────────────┐ │
│         │ 光学トラッキング            │  Python 同期計測       │ │
│         │                            │  スクリプト            │ │
│   （カメラ群）                        │  ・NatNetClient (受信) │ │
│                                      │  ・高さで ID 自動判別  │ │
│                                      │  ・pyserial (VNA制御)  │ │
│   ┌────────────────┐   USB           │  ・threading.Lock      │ │
│   │ JNCRadio VNA 3G│ ◀──(COMポート)──▶│  で同期               │ │
│   │  PORT1 = S11   │   115200 bps     └──────────┬───────────┘ │
│   └────────────────┘                            │             │
│         ▲                                        ▼             │
│   （メアンダコイル服 = DUT）              sync_dataset.csv       │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 必要なハードウェア

| 機器 | 役割 | 備考 |
|------|------|------|
| **Windows PC（ThinkPad）** | Motive と Python スクリプトを同時実行する計測ホスト | 後述の通り高負荷になるため、できる限り高性能な機体を推奨 |
| **OptiTrack システム（カメラ群 + Motive）** | 腕に取り付けた 3 個の対象の 3 次元位置をリアルタイム取得 | Motive のライセンスおよびキャリブレーション済みのキャプチャ空間が必要 |
| **JNCRadio VNA 3G** | 12.5–14.5 MHz を掃引して S11（反射係数）を測定 | USB Type-C ケーブルで PC に接続。シリアル（仮想 COM ポート）として認識される |
| **メアンダコイル服（DUT）** | 被測定物 | VNA の **PORT1**（S11 測定ポート）に接続。上腕・関節・前腕に各 1 個、計 3 個の反射マーカーを貼付 |

### 1.3 ソフトウェア動作環境

- **OS:** Windows 10 / 11
- **Python:** 3.8 以上（64bit 推奨）
- **Motive:** OptiTrack 純正ソフトウェア（Data Streaming 対応バージョン。NatNet 4.x / Motive 3.1 系で動作確認）
- **NatNet SDK:** OptiTrack 公式 SDK（`NatNetClient.py` を使用）

## 2. セットアップ（環境構築）

### 2.1 Python ライブラリのインストール

コマンドプロンプト（または PowerShell）で以下を実行してください。

```bash
pip install pyserial scikit-rf matplotlib numpy pandas
```

| ライブラリ | 用途 |
|-----------|------|
| `pyserial` | JNCRadio VNA 3G とのシリアル（COM ポート）通信 |
| `scikit-rf`（skrf） | **必須**。掃引した S11 をインピーダンス Z11 に変換 |
| `matplotlib` | **必須**。GUI 内のリアルタイムグラフ描画 |
| `numpy` | **必須**。配列演算（skrf/matplotlib の依存でもある） |
| `pandas` | 取得後のデータセットの読み込み・解析（後処理用、計測本体には任意） |

> **補足:** 計測本体の動作には `pyserial` / `scikit-rf` / `matplotlib` / `numpy` が必要です（`scikit-rf` をインストールすると `numpy` / `scipy` / `matplotlib` も併せて入ります）。`pandas` は取得済み CSV の後処理用で任意です。
> GUI に使う `tkinter` は **Python 標準ライブラリ**のため追加インストールは不要です（Windows の公式インストーラには標準で含まれます。最小構成等で `import tkinter` に失敗する場合のみ、Python を「tcl/tk」付きで入れ直してください）。

### 2.2 `NatNetClient.py` の配置（重要）

OptiTrack との通信には、OptiTrack が公式に配布する **NatNet SDK 同梱の Python サンプル `NatNetClient.py`** を使用します。これは `pip` では入手できません。本スクリプトは以下の **2 箇所のいずれか**に SDK ファイルがあれば自動で読み込みます（`sys.path` に自動追加）。

- **(A) 同梱 SDK をそのまま使う場合:** リポジトリ内の `./NatNetSDK/Samples/PythonClient/` に `NatNetClient.py` 等が置かれていれば、追加作業は不要です。
- **(B) 手動配置する場合:** OptiTrack 公式サイト（または Motive インストールフォルダ）から **NatNet SDK** を入手し、以下のファイルを **本体スクリプトと同じフォルダ**にコピーします。
  - `NatNetClient.py`（必須）
  - `MoCapData.py`（**必須**。フレームデータ（Rigid Body / Labeled Marker）の構造を解釈するために使用します）
  - `DataDescriptions.py`（**必須**。`NatNetClient.py` が内部で import します）

想定するフォルダ構成は以下のいずれかです。

```
# (A) 同梱 SDK 構成（このリポジトリの構成）
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── README.md
└── NatNetSDK/
    └── Samples/
        └── PythonClient/
            ├── NatNetClient.py
            ├── MoCapData.py
            └── DataDescriptions.py

# (B) 手動配置構成
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── NatNetClient.py
├── MoCapData.py
├── DataDescriptions.py
└── README.md
```

> **対応バージョン:** 本スクリプトは **NatNet 4.x（Motive 3.1 系）** の `NatNetClient.py` に合わせて実装しています。フレーム受信には `new_frame_with_data_listener`（`data_dict["mocap_data"]` に `MoCapData` を渡す）を使用します。

## 3. 事前設定の手順

計測を開始する前に、Motive 側と JNCRadio VNA 3G 側の双方で設定を済ませておく必要があります。

### 3.1 Motive（OptiTrack）側の設定

Motive を起動し、キャプチャ空間のキャリブレーションを済ませたうえで、**Data Streaming** パネルを設定します。**個別の名前付けや ID の控えは不要**です（高さで自動判別するため）。

#### (a) 3 個の対象の準備【最重要】

本システムは **名前や ID ではなく「開始時の高さ」で対象を識別**します。Motive 側で以下を満たしてください。

1. 上腕・関節・前腕のそれぞれに反射マーカーを **1 個ずつ（計 3 個）** 取り付けます。
2. 3 個の対象を、**リジッドボディ**（Rigid Body）または **ラベル付きマーカー**（Labeled Marker）として配信できる状態にします（どちらでも自動判別します。スクリプトの `OBJECT_SOURCE` 参照）。
3. **計測対象は 3 個だけが配信されるようにします。** 余分なマーカー／リジッドボディがキャプチャ空間に存在すると、どの 3 つを使うか判別できません（高さ順の「中間＝関節」が一意に決まらないため）。不要な対象は Motive 側で除外してください。
4. **キャリブレーション開始時の姿勢が重要です。** プログラム起動直後（最初の有効フレーム）に、**3 対象が高さ順（上腕 ＞ 関節 ＞ 前腕）に明確に並ぶ姿勢**にしてください。腕を曲げて関節が上腕より高くなっている等の状態で開始すると、誤って判別されます。

> **ID を控える必要も、名前を付ける必要もありません。** 高さの大小関係さえ正しく取れていれば、実行ごとに ID が変わっても自動で割り当てられます。

#### (b) Data Streaming の設定

1. メニューから **Data Streaming** パネルを開きます。
2. **Broadcast Frame Data** を **ON（有効）** にします。
3. **Local Interface** を **`127.0.0.1`（localhost / loopback）** に設定します。
   - 同一 PC 内でデータを受け渡すため、外部ネットワークではなくループバックアドレスを指定するのが要点です。
4. **Transmission Type** を **Unicast** に設定します。
   - 同一 PC 内のループバック通信では Multicast よりも Unicast の方が安定します。本スクリプトも Unicast 前提（`set_use_multicast(False)`）で実装されています。
5. 対象の扱い方に応じて、配信を **ON** にします。
   - リジッドボディとして扱う場合: **Rigid Bodies** を ON。
   - ラベル付きマーカーとして扱う場合: **Markers**（Labeled Markers）を ON。
   - これらが無効だと座標が配信されず、自動判別もできません。

> **高さの座標軸について（重要）:** 本スクリプトは既定で **Y 座標**を「高さ」として扱います（NatNet の既定配信は Y-Up のため）。Motive を **Z-Up** でストリーミングしている場合は、スクリプトの `HEIGHT_AXIS_INDEX` を `2`（Z）に変更してください（§4.1 参照）。

### 3.2 JNCRadio VNA 3G 側の設定

#### (a) COM ポート番号の確認

1. USB Type-C ケーブルで JNCRadio VNA 3G を PC に接続します。
2. **デバイスマネージャー** を開きます（`Win + X` → 「デバイス マネージャー」）。
3. **「ポート (COM と LPT)」** の項目を展開します。
4. 接続した VNA に対応する仮想シリアルポート（例: `USB Serial Device (COM3)`）を確認し、**COM 番号**を控えます。
   - 接続前後でデバイスマネージャーを見比べると、新たに増えたポートが VNA に対応するものです。
   - この COM 番号を後述の `NANOVNA_PORT` に設定します。

> JNCRadio VNA 3G のシリアルボーレートは適応式ですが、本体・スクリプトともに **115200 bps** を使用します（マニュアル §7 準拠）。

#### (b) キャリブレーション（SOLT）の事前実施【強く推奨】

S11 を正確に測定するため、**計測を開始する前に本体側で校正（キャリブレーション）を済ませておくこと**を強く推奨します。

1. メアンダコイル服を接続する **PORT1（S11 測定ポート）** に対して、付属の校正キットを用いて **SOLT 校正** を行います。
   - **S** = Short（短絡）
   - **O** = Open（開放）
   - **L** = Load（50 Ω 終端負荷）
   - **T** = Through（PORT1–PORT2 間。S11 のみであれば省略可）
2. マニュアル §4.4 / §7.2.14（`cal` コマンド）の手順に従い、各標準器を接続して校正を実施します。校正後は必ず校正データを保存（`save {id}` または本体メニュー）してください。
3. 掃引範囲（12.5–14.5 MHz）全体を含む周波数範囲で校正されていることを確認します。

> **重要:** 未校正のまま測定すると S11 が不正確になり、後段で算出されるインピーダンス Z も信頼できない値になります。データセットの品質を担保するため、校正は必ず実施してください。

> **校正について:** 本システムは **S11（PORT1 の反射）固定**で計測します。PORT1 の反射校正（最低でも Open / Short / Load）を実施し、被測定物（メアンダコイル服）を PORT1 に接続してください。

## 4. 使い方（実行手順）

### 4.1 スクリプト内変数の書き換え

`sync_optitrack_nanovna.py` の冒頭にある **設定ブロック**を、ご自身の環境に合わせて編集します。

```python
# --- NanoVNA / JNCRadio VNA-3G (シリアル) ---
NANOVNA_PORT   = "COM3"        # GUI の COM ポート一覧の「初期選択候補」（実際は画面で選択）
NANOVNA_BAUD   = 115200        # ボーレート（通常は変更不要）
Z0             = 50.0          # 特性インピーダンス [Ω]（通常は 50）

# --- 掃引（スイープ）範囲 ---
# 12.5-14.5MHz を 101 点で掃引し、毎フレーム 101 点分の複素 S11 を一括取得する。
SWEEP_START_HZ = 12_500_000    # 掃引開始 [Hz]（12.5 MHz）
SWEEP_STOP_HZ  = 14_500_000    # 掃引終了 [Hz]（14.5 MHz）
SCAN_POINTS    = 101           # 掃引点数
FREQ_GRID_HZ   = np.linspace(SWEEP_START_HZ, SWEEP_STOP_HZ, SCAN_POINTS)  # 共通基準
TARGET_FREQ_HZ = 13_560_000    # 参考: グラフの縦線マーカー（13.56 MHz）

# --- 計測する S パラメータ（S11 固定） ---
# scan の outmask: bit0(=1)=周波数, bit1(=2)=S11 →「周波数+S11」(=3) を出力させる。
VNA_SPARAM  = "S11"
VNA_OUTMASK = 2

# --- OptiTrack (NatNet) ---
NATNET_SERVER_IP = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_LOCAL_IP  = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_USE_MULTICAST = False    # 同一PCループバックは Unicast 推奨（通常は変更不要）

# --- 自動判別（キャリブレーション）方式 ---
# 高さに使う座標軸: 0=X, 1=Y, 2=Z。NatNet既定はY-Upなので 1（=Y）。
# Motiveを Z-Up 配信にしている場合は 2 に変更する。
HEIGHT_AXIS_INDEX = 1
# 判別に使うソース: "rigid_body" / "labeled_marker" / "auto"
#   "auto" はリジッドボディがあればそれを、無ければラベル付きマーカーを使う。
OBJECT_SOURCE = "auto"
EXPECTED_OBJECT_COUNT  = 3      # 判別に必要な対象数（上腕・関節・前腕の 3 個）
CALIBRATION_TIMEOUT_SEC = 10.0  # 自動判別が完了するまで待つ最大秒数

SKIP_OCCLUDED = True            # 隠れ（オクルージョン）中・トラッキング無効中は更新をスキップ

# --- 出力 ---
OUTPUT_CSV = "sync_dataset.csv" # 保存ダイアログに出す初期ファイル名（実際の保存先は実行時に選択）
```

最低限、以下を環境に合わせて変更してください。

| 変数 | 設定内容 |
|------|---------|
| `NANOVNA_PORT` | COM ポート一覧の初期選択候補（実際の接続先は **GUI で選択**するため必須ではない） |
| `SWEEP_START_HZ` / `SWEEP_STOP_HZ` | 掃引範囲（既定 12.5–14.5 MHz） |
| `SCAN_POINTS` | 掃引点数（既定 101）。CSV 列数・グラフ点数に直結 |
| `TARGET_FREQ_HZ` | グラフに引く参考縦線の周波数（既定 13.56 MHz） |
| `HEIGHT_AXIS_INDEX` | 高さに使う軸。Y-Up 配信なら `1`、**Z-Up 配信なら `2`** |
| `OBJECT_SOURCE` | 対象の配信形態に合わせて `"rigid_body"` / `"labeled_marker"` / `"auto"` |

> **COM ポートについて:** どの COM ポートに接続するかは **GUI のドロップダウンで選択**します（コード編集は不要）。`NANOVNA_PORT` はその初期選択候補にすぎません。

> **注意:** 自動判別は「開始時の高さの大小関係」に依存します。プログラム起動時に **3 対象が上腕＞関節＞前腕の順で明確に並ぶ姿勢**にしてください。また、`HEIGHT_AXIS_INDEX` が Motive の配信座標系（Y-Up / Z-Up）と合っていないと、高さが正しく取れず誤判別します。

### 4.2 起動と GUI 操作

Motive を起動して Data Streaming を有効化し、VNA を USB 接続した状態で、以下を実行します。

```bash
python sync_optitrack_nanovna.py
```

実行すると **操作画面（GUI）** が立ち上がります。次の流れで操作します。

#### ステップ 0: COM ポートを選ぶ

- 画面上部の「COM Port」ドロップダウンに、PC が認識しているシリアルポートが自動でリストアップされます（例: `COM3 - USB Serial Device (COM3)`）。VNA が接続されている COM ポートを選択してください。
- **VNA を後から挿した／一覧に出ない場合**は、隣の **［ポート再検索］** ボタンを押すと一覧が更新されます（プログラムの再起動は不要）。
- どの COM ポートか分からない場合は、VNA を抜き差しして増減するポートが目印です（デバイスマネージャーの「ポート (COM と LPT)」でも確認できます）。
- **VNA 実機が無いとき**は、一覧末尾の **「None（VNAなしテストモード）」** を選びます。VNA をスキップして OptiTrack のみ取得し、VNA 列にはダミー値 0 が入ります（OptiTrack 受信・保存の動作確認用）。
- この選択は **［計測開始］を押した時点で確定**します。計測中は COM ポート変更・再検索はできません（停止後に再選択可能）。

#### ステップ 1: ［計測開始］を押す

- 計測（データ取得）がバックグラウンドで開始します。
- このとき **最初の有効フレーム**で「高さ順の自動判別」が走り、`UpperArm ＞ Joint ＞ Forearm` のマッピングが確定します。
- **押す瞬間の姿勢が重要です。** 3 対象が上腕＞関節＞前腕の高さ順に明確に並ぶ姿勢で開始してください（§3.1 参照）。
- 画面の「状態」表示と「サンプル数」、およびログ欄で進行状況を確認できます。確定結果はログとコンソールの両方に出力されます。

```
（ログ欄・コンソールの例）
計測を開始します。COM Port = COM3（S11 を計測）
VNA 接続 OK: COM3 @ 115200bps / 掃引 12.50-14.50 MHz 101点を記録 (S11)
OptiTrack 受信開始。最初の有効フレームで自動判別します...
自動判別 完了: UpperArm=id4 / Joint=id2 / Forearm=id7
計測中...
```

> **ポイント:** `UpperArm=id4` のように、**実行ごとに変わる ID が開始時の高さから自動的に割り当てられ**、以後はその ID で固定されます。次回 ID が変わっても、開始姿勢さえ正しければ設定変更なしでそのまま動作します。
>
> **接続失敗時:** 選択した COM ポートが開けない（存在しない／他ソフトが占有）場合は、警告ポップアップが表示されます。COM ポートを選び直す（必要なら［ポート再検索］）か、占有しているソフト（nanovna-saver 等）を閉じてから、再度［計測開始］してください。

#### ステップ 2: ［計測終了 / 保存］を押す

- 計測を停止し、内部に溜めていたデータを書き出す準備をします。
- 直後に **ファイル保存ダイアログ**（`tkinter.filedialog.asksaveasfilename`）が表示されるので、**保存先フォルダと CSV ファイル名**を指定します。
- ファイル名を決定すると CSV が保存され、保存完了のメッセージののち **GUI が安全に閉じてプログラムが終了**します。
- 保存をキャンセルした場合はデータ破棄の確認が出ます（破棄して終了するか、保存ダイアログをやり直すか選べます）。

> **データの保持方式:** 計測中のデータは**メモリ上に蓄積**され、終了時にまとめて 1 つの CSV に書き出します。途中経過を逐次ファイルに書く方式ではないため、保存はステップ 2 で必ず行ってください（長時間計測でメモリ使用が気になる場合はご相談ください）。

### 4.3 終了とクリーンアップ（重要）

終了の方法は次の 3 通りで、**いずれの場合も** VNA のクローズ・NatNet の切断・全スレッドの join を確実に実行してから終了します。

1. **［計測終了 / 保存］ボタン** … 推奨。保存ダイアログ → CSV 保存 → 終了。
2. **ウィンドウの ×（閉じる）** … 計測中なら確認のうえ停止・クリーンアップし、保存ダイアログを表示してから終了します。
3. **致命的エラー時**（VNA 切断など）… エラーを通知して計測を畳み、再度［計測開始］できる状態に戻します。

クリーンアップでは以下を順に実施します。

1. 計測ワーカースレッドへ停止を要求し、`join` で終了を待つ。
2. VNA に `resume` を送って掃引表示を元に戻し、シリアルポート（COM ポート）を閉じる。
3. NatNet クライアントを `shutdown()` し、受信スレッドと UDP ソケットを解放する。

> **【バグ修正】2 回目以降の起動でフリーズしないために。**
> これらの解放処理を「終了経路すべてで・冪等に」行うことで、COM ポートや UDP ソケット、受信スレッドが確実に解放されます。以前発生していた「一度実行して終了したあと、次の実行で `Ctrl + C` を受け付けずフリーズする」問題は、この厳密なクリーンアップにより解消されています。GUI 運用のため計測の開始・停止はボタンで行い、`Ctrl + C` には依存しません。

## 5. 出力データ構造（CSV ヘッダー解説）

出力ファイル（終了時の保存ダイアログで指定。初期名: `sync_dataset.csv`）は、**1 行 = 位置情報（10 列）＋ 各掃引周波数のデータ（101 点 × 4 列）= 414 列**のワイド形式 CSV です。位置データは **上腕・関節・前腕の 3 個 × (X, Y, Z) = 9 値**が含まれ、各座標は対応する対象の中心座標（Motive の配信座標系、単位はメートル）です。

> **座標系について:** 本システムは Motive で設定された配信座標系の値をそのまま記録します。NatNet の既定は **Y-Up**（Y 軸が鉛直上向き）ですが、Motive の設定により **Z-Up** に変更されている場合もあります。解析時・および `HEIGHT_AXIS_INDEX` の設定時は、Motive 側の座標系設定に合わせて軸の向きを解釈してください。

**先頭 10 列（位置情報）**

| カラム名 | 意味 | 単位 |
|----------|------|------|
| `Timestamp` | 各サンプルを記録した PC のローカル時刻（ISO 8601 形式、ミリ秒精度） | — |
| `UpperArm_X/Y/Z` | **上腕**の中心 X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `Joint_X/Y/Z` | **関節**の中心 X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `Forearm_X/Y/Z` | **前腕**の中心 X/Y/Z 座標（Motive 座標系） | メートル [m] |

**以降 404 列（掃引データ）** — 掃引周波数ごとに 4 列が、**12.5MHz から 14.5MHz まで 101 周波数分**繰り返されます（列名末尾は MHz 表記）。

| カラム名（例: 12.5 MHz） | 意味 | 単位 |
|----------|------|------|
| `S11_Real_12.5` | その周波数の反射係数 S11 の**実部** | 無次元（線形） |
| `S11_Imag_12.5` | その周波数の反射係数 S11 の**虚部** | 無次元（線形） |
| `Z_R_12.5` | `scikit-rf` で換算した複素インピーダンス Z11 の**実部（抵抗 R）** | オーム [Ω] |
| `Z_X_12.5` | `scikit-rf` で換算した複素インピーダンス Z11 の**虚部（リアクタンス X）** | オーム [Ω] |
| …（`12.52`, `12.54`, … `14.5` まで 101 セット） | | |

> ある対象がトラッキングロスト等で未受信の場合、その対象の X/Y/Z セルは空欄になります。

> **VNAなしテストモードの場合:** 掃引データ 404 列すべてにダミー値 `0` が入ります（OptiTrack の座標列は通常どおり記録されます）。

### 5.1 同期の仕組み

OptiTrack の更新レート（数百 Hz）と VNA の掃引取得レート（1 掃引あたり数十〜数百 ms）には大きな差があります。本システムでは、NatNet 受信スレッドがフレームのたびに **起動時に確定した ID→部位のマッピング**を使って 3 対象の座標を `threading.Lock()` 下で「対象ごとの最新座標」として更新し続けます。一方、**計測ワーカースレッド**が VNA の **101 点掃引を 1 回取得し終えた「その瞬間」**に、上腕・関節・前腕 3 対象の最新座標を同一ロック下で一括スナップショットして結合し、1 行としてメモリに蓄積します。すなわち CSV の 1 行は、「ある掃引（101 点の S11/Z）」と「その掃引完了時点で最も新しい 3 対象（計 9 値）の位置データ」をまとめたものです。

ロックは 3 対象まとめて取得する間だけ保持されるため、読み出しの途中で一部の対象だけが更新される（行内で対象ごとに時刻がずれる）ことはありません。GUI（メインスレッド）・計測ワーカー・NatNet 受信スレッドは分離されているため、計測中も画面操作が固まりません。

### 5.2 インピーダンスへの変換（scikit-rf）

掃引した 101 点分の複素 S11 を `scikit-rf` の `Network` オブジェクトに変換し、特性インピーダンス **Z₀ = 50 Ω** 基準でインピーダンス **Z11** を求めて `Z_R`・`Z_X` に記録します。

```python
import skrf as rf, numpy as np
s = np.asarray(s11_array, dtype=complex).reshape(-1, 1, 1)   # (101, 1, 1)
freq = rf.Frequency.from_f(FREQ_GRID_HZ, unit="Hz")
ntwk = rf.Network(frequency=freq, s=s, z0=50)
z11 = ntwk.z[:, 0, 0]          # 各周波数の複素インピーダンス
Z_R, Z_X = z11.real, z11.imag  # 実部(抵抗) / 虚部(リアクタンス)
```

数式的には反射係数から `Z = Z0 × (1 + S11) / (1 − S11)` を全点に適用したものです。生の S11 と換算後の Z の双方を保存しているため、後処理で別の Z₀ を用いた再計算や、S11 ベースの解析（リターンロス・VSWR 等）も柔軟に行えます。

### 5.3 リアルタイムグラフ

計測中、GUI 内に **周波数 vs インピーダンス**のグラフ（matplotlib を tkinter に埋め込み）が表示されます。

- 横軸: 周波数 [MHz]（12.5–14.5 MHz）
- 縦軸: インピーダンス [Ω]
- 線: **Z_R（抵抗, 赤）** と **Z_X（リアクタンス, 青）** を色分け表示。13.56 MHz に参考の縦線。
- 腕を動かすと、各掃引の最新 Z11 にあわせてグラフがリアルタイム更新され、**どの帯域で整合がずれているか（共振点の移動）**を視覚的に確認できます。

> 描画は GUI のポーリング（約 10 fps）ごとに「その間に届いた最新の掃引 1 件」だけを反映する間引き方式のため、高速サンプリングでも GUI が重くなりません。VNAなしテストモードでは全点 0 の平坦な線が表示されます。

## 6. 自動判別の仕組み（技術解説）

実行ごとに変わる ID を直接扱う代わりに、**計測開始時の高さの大小関係から ID と部位を自動的に対応付け**ます。処理の流れは次の通りです。

1. **対象の収集（毎フレーム）（`collect_frame_objects()`）**
   フレーム受信時に、`OBJECT_SOURCE` に従って `(ID, 座標)` のリストを集めます。
   - `"rigid_body"` … リジッドボディのみ
   - `"labeled_marker"` … ラベル付きマーカーのみ
   - `"auto"` … リジッドボディがあればそれを、無ければラベル付きマーカーを使用
   `SKIP_OCCLUDED = True` の場合、トラッキング無効（リジッドボディの `tracking_valid` が False）やオクルージョン中の対象は除外します。

2. **自動判別（起動後の最初の有効フレームで 1 回）（`try_calibrate()`）**
   有効な対象が **ちょうど 3 個**揃ったら、各対象の高さ（`HEIGHT_AXIS_INDEX` 軸の座標）で**降順ソート**し、
   - 1 番高い → `UpperArm`
   - 2 番目 → `Joint`
   - 1 番低い → `Forearm`

   として `ID → 部位` の対応表を確定します（`threading.Event` で 1 回だけ実行）。
   有効な対象が 3 個に満たない場合は確定を保留し、後続フレームで再試行します。逆に **4 個以上**ある場合は中間（Joint）が一意に決まらないため確定せず、警告を出します（余分な対象を Motive 側で外すか `OBJECT_SOURCE` を見直してください）。

3. **毎フレームの座標抽出（2 フレーム目以降）**
   確定済みの `ID → 部位` マップを使い、フレーム内の各対象を ID で照合して該当部位の最新座標 (X, Y, Z) を更新します。ID は計測終了まで固定されます。

この設計により、**Motive 側で名前付けや ID 設定をしなくても、開始姿勢さえ正しければ自動的に正しく紐付け**できます。なお判別は起動時の 1 回のみです。途中で対象を入れ替えた場合や開始姿勢を誤った場合は、スクリプトを再起動して判別をやり直してください。

## 7. 注意事項・トラブルシューティング

### 7.1 自動判別が完了しない / OptiTrack のデータが受信できない場合

［計測開始］後に「自動判別が完了しません」や「有効な対象が N 個あります（期待値 3）」がログ欄／コンソールに出る、または座標カラムが空欄になる場合は、以下を確認してください。

- **3 対象がすべて同時にトラッキングされているか。** いずれかがロスト（オクルージョン等）していると、有効な対象が 3 個に満たず判別できません。Motive のビューで 3 個すべてが安定して見えているか確認してください。
- **余分な対象が配信されていないか。** `有効な対象が N 個あります（期待値 3）` が出る場合、判別対象以外のマーカー／リジッドボディが映り込んでいます。Motive 側で不要な対象を外すか、`OBJECT_SOURCE` を `"rigid_body"` / `"labeled_marker"` に絞って候補を限定してください。
- **`OBJECT_SOURCE` が配信形態と合っているか。** リジッドボディで配信しているのに `"labeled_marker"` を指定している（またはその逆）と対象が集まりません。`"auto"` にすると両対応です。
- **`HEIGHT_AXIS_INDEX` が配信座標系と合っているか。** Y-Up 配信なら `1`、Z-Up 配信なら `2`。これが合っていないと「高さ」が正しく取れず、判別はできても**上下が入れ替わる**ことがあります。確定ログの高さの値が妥当か確認してください。
- **開始姿勢が高さ順になっているか。** 起動時に上腕＞関節＞前腕の高さ順でないと、別の部位に割り当てられます。腕を自然に下ろす等、高さ差が明確な姿勢で起動してください。
- **Motive の Data Streaming が ON か。** `Broadcast Frame Data` を有効にし、対象に応じて **Rigid Bodies** または **Markers（Labeled Markers）** を ON にしてください。
- **Local Interface が `127.0.0.1`（localhost）か。** 別の NIC が選択されているとループバックでは受信できません。
- **Transmission Type が Unicast か。** 本スクリプトは Unicast 前提です。Multicast の場合は `NATNET_USE_MULTICAST = True` に変更してください。
- **Windows ファイアウォール。** ループバック通信は通常ブロックされませんが、セキュリティソフトが UDP 通信を遮断している場合は、Python（`python.exe`）の通信を許可してください。
- **`NatNetClient.py` / `MoCapData.py` / `DataDescriptions.py` が読み込めるか。** これらが見つからないと import に失敗し、OptiTrack なしで続行されて座標は空欄になります。同梱の `./NatNetSDK/Samples/PythonClient/` か、本体スクリプトと同じフォルダに配置してください。

### 7.2 上下や部位が入れ替わって判別される場合

- **高さの軸（`HEIGHT_AXIS_INDEX`）を確認。** Z-Up 配信なのに `1`（Y）のままだと、高さとして水平方向の値を見てしまい誤判別します。
- **開始時の姿勢を確認。** 関節を上腕より高く上げた状態などで開始すると、その高さ関係のまま割り当てられます。一度［計測終了 / 保存］で停止し、正しい姿勢で再度［計測開始］してください（判別は開始ごとにやり直されます）。
- **確定ログの高さの値を確認。** `(高さ Y=1.320)` のような値が、実際の上腕・関節・前腕の高さと整合しているかをチェックすると原因切り分けが容易です。

### 7.3 COM ポートが開けない / VNA に接続できない場合

［計測開始］時に **「VNAの接続に失敗しました。COM番号が正しいか、他のソフトが占有していないか確認してください」** という警告ポップアップが出る場合は、以下を確認してください（プログラムはクラッシュせず、再選択して再開できます）。

- **正しい COM ポートを選んでいるか。** GUI の「COM Port」ドロップダウンで、VNA に対応するポートを選び直してください。一覧に出ない場合は VNA を接続し直し、**［ポート再検索］** ボタンで一覧を更新します。
- **どのポートか分からないとき。** VNA を抜いて［ポート再検索］→挿して［ポート再検索］とし、増減したポートが VNA です（デバイスマネージャーの「ポート (COM と LPT)」でも確認可）。
- **他のソフトがポートを占有していないか。** **nanovna-saver や JNCRadio 純正 PC ソフト、シリアルターミナル（PuTTY 等）** が同じ COM ポートを開いていると、Python からはアクセスできません（`FileNotFoundError` / `アクセス拒否` 等）。**それらのソフトを必ず閉じてから**やり直してください。
- **VNA の電源が入っているか／ケーブルがデータ通信対応か。** 充電専用ケーブルではシリアルが認識されません。
- **ドライバ。** ポートが現れない場合は USB シリアルドライバの再インストールを検討してください。

### 7.4 S11 が全反射（≈1）になる / 13.56MHz の共振が見えない場合

`S11_Real` がほぼ 1（全反射）になる、共振の落ち込みが見えない場合は、以下を確認してください。

- **掃引範囲が共振点を含んでいるか。** `SWEEP_START_HZ`〜`SWEEP_STOP_HZ`（既定 12.5–14.5 MHz）が対象の共振点を含むか確認してください。本バージョンは初期化時に `sweep` コマンドで範囲を固定し、101 点全体を記録します（グラフで共振の落ち込みが範囲内に見えるか確認）。
- **キャリブレーション（校正）が済んでいるか。** これが S11≈1 の最も多い原因です。**未校正だと S11 はほぼ全反射になります。** 掃引範囲（12.5–14.5 MHz）を含む範囲で PORT1 の反射校正（Open / Short / Load）を実施してください（§3.2(b)）。校正範囲が掃引範囲を含まないと、補間が効かず不正確になります。
- **DUT が正しく PORT1 に接続されているか。** ケーブル断・接触不良・未接続でも全反射になります。
- **本当に整合が取れているか。** 共振点でも整合が不十分なら反射は大きくなります。NanoVNA 本体の画面（または nanovna-saver）で共振（S11 の落ち込み）が掃引範囲内に見えるか、まず単体で確認すると切り分けが容易です。

### 7.5 GUI が出ない / 2 回目の起動でフリーズする場合

- **GUI が表示されない（`ModuleNotFoundError: No module named 'tkinter'` 等）。** `tkinter` は標準ライブラリですが、最小構成の Python だと含まれないことがあります。tcl/tk 付きで Python を入れ直してください（Windows 公式インストーラは標準で同梱）。
- **2 回目以降の起動でフリーズする。** 本バージョンでは終了時に VNA・NatNet・スレッドを確実に解放するため、通常は発生しません。それでも起きる場合は、**前のプロセスが残っていないか**を確認してください（タスクマネージャーで `python.exe` / `pythonw.exe` を終了）。残存プロセスが COM ポートや UDP ポート（1510/1511）を掴んでいると、次回起動が阻害されます。
- **`[ERROR] VNA シリアル通信が切断されました` が出た場合。** ケーブルの抜けや本機のスリープが原因です。エラー通知後は計測が畳まれ再度［計測開始］できる状態に戻るので、接続を確認してからやり直してください。
- **保存をキャンセルしたとき。** データ破棄の確認が出ます。「いいえ」を選ぶと保存ダイアログをやり直せます（蓄積済みデータはプロセス終了まで保持されます）。

### 7.6 高負荷時のデータドロップ対策（重要）

同一 PC 上で **Motive（リアルタイム 3D 描画）** と **Python 計測スクリプト**を同時に高負荷で動作させるため、CPU/GPU リソースの競合により OptiTrack のフレーム取りこぼし（ドロップ）が発生することがあります。これを防ぐための実践的なテクニックを示します。

- **計測中は Motive のウィンドウを最小化する。** Motive の 3D ビューポートの描画は GPU/CPU を大きく消費します。Data Streaming（データ配信）自体はウィンドウを最小化しても継続されるため、**計測開始後は Motive を最小化して描画負荷を下げる**ことで、ドロップを大幅に削減できます。
- **不要なアプリケーションを終了する。** ブラウザや他の重いアプリを閉じ、リソースを計測に集中させます。
- **電源プランを「高パフォーマンス」に設定する。** ThinkPad の省電力設定によるクロック低下を防ぎます。可能であれば AC 電源に接続してください。
- **Motive の描画設定を軽くする。** 描画レート（Viewport の更新頻度）やトレイル表示などを抑えると、さらに負荷を下げられます。
- **掃引点数・範囲を見直す。** `SCAN_POINTS` を大きく、`SWEEP_START_HZ`〜`SWEEP_STOP_HZ` を広くするほど 1 掃引の取得時間が延び、全体のスループット（OptiTrack との同期レート）が低下します。必要な帯域だけに範囲を狭め、点数を絞ると高速化できます（CSV 列数・グラフ点数も減ります）。
