# OptiTrack × JNCRadio VNA 3G リアルタイム同期計測システム

メアンダコイル服（ウェアラブルアンテナ／コイル）の**3次元位置**と**高周波特性（S11・インピーダンス）**を、同一 Windows PC 上で同時かつ同期的に取得し、機械学習・解析用の CSV データセットとして保存するための Python アプリケーションです。

位置トラッキングは身体に取り付けた **7 個のラベル付きマーカー**（**R_forearm / R_joint / R_upperarm / chest / L_forearm / L_joint / L_upperarm**）を対象とします。**Motive 側で各マーカーにラベル（名前）を付けてアセット配信**し、本システムは**ラベル付きマーカーの `marker_id`（1〜7）を名前に対応付けて**座標を取得します（後述「ラベル認識の仕組み」）。

VNA は **nanoVNA を 2 台同時に接続**でき、それぞれ別の対象（**leftbody / rightbody**）の S11 を並行して計測します（チャンネル名・台数は `VNA_CHANNEL_NAMES` で変更可能）。各 VNA は **12.5–14.5 MHz を 101 点で掃引**し、毎フレーム 101 点分の S11 を取得して `scikit-rf` でインピーダンス **Z11** に変換します。OptiTrack の 7 マーカーの座標と **2 台ぶんの掃引データ**をマルチスレッドかつスレッドセーフに結合し、**1 行に「位置情報 ＋ leftbody の掃引 ＋ rightbody の掃引」を並べた**以下の形式で記録します（VNA 列は `leftbody_` / `rightbody_` で区別され、どちらの対象のインピーダンスか判別できます）。

```
[Timestamp,
 R_forearm_X,  R_forearm_Y,  R_forearm_Z,
 R_joint_X,    R_joint_Y,    R_joint_Z,
 R_upperarm_X, R_upperarm_Y, R_upperarm_Z,
 chest_X,      chest_Y,      chest_Z,
 L_forearm_X,  L_forearm_Y,  L_forearm_Z,
 L_joint_X,    L_joint_Y,    L_joint_Z,
 L_upperarm_X, L_upperarm_Y, L_upperarm_Z,
 leftbody_S11_Real_12.5,  leftbody_S11_Imag_12.5,  leftbody_Z_R_12.5,  leftbody_Z_X_12.5,
 ... (leftbody の各掃引周波数ごとに 4 列, 終了周波数まで) ...,
 rightbody_S11_Real_12.5, rightbody_S11_Imag_12.5, rightbody_Z_R_12.5, rightbody_Z_X_12.5,
 ... (rightbody の各掃引周波数ごとに 4 列, 終了周波数まで) ...]
```

計測中は GUI 上に **leftbody / rightbody それぞれのスミスチャート**（S11=反射係数 Γ をプロット）がリアルタイム表示され、さらに **GUI で指定した「読み取り周波数」でのインピーダンス Z = R + jX を各 body について数値表示**します。腕を動かすと整合のずれ（Γ の軌跡・共振点の移動）が視覚的に確認でき、狙った周波数での R/X 値も即座に読み取れます。

> **【重要】マーカーは「ラベル（`marker_id` の並び）」で識別します。**
> 各マーカーの名前はフレームデータには含まれません。Motive はラベル付きマーカーを **`marker_id`（アセット内の 1 始まりの番号）** 付きで毎フレーム配信します。本システムは設定 `EXPECTED_MARKER_NAMES` にこの並びを記述しておき、**`marker_id = i` のマーカーを `EXPECTED_MARKER_NAMES[i-1]` に対応付け**ます（高さによる自動判別は廃止）。実際にどの `marker_id` がどの部位かは、**起動直後に GUI ログへ出力される診断ログ**（`MARKER_DIAGNOSTIC_FRAMES`）で各マーカーの座標を確認して合わせます。マーカーセット配信を使う場合は `MARKER_SOURCE = "marker_set"` に切り替えられます。

> **【重要】マーカーが 1 個でも認識できないサンプルは自動破棄します。**
> いずれかのマーカーが認識できない（オクルージョン／未検出）フレームでは、そのとき取得した VNA サンプルを CSV に**記録せず破棄**します。これにより「消失中のマーカーの古い座標がそのまま記録される」ことを防ぎ、全マーカーが揃った行だけがデータセットに残ります。隠れマーカーは occluded フラグ付き、または `(0,0,0)` で配信されるため、原点近傍を「未認識」とみなします（`OCCLUSION_ORIGIN_EPS`）。

> **【VNA 2 台の同時計測】nanoVNA を 2 台つないで別々の対象（leftbody / rightbody）を計測できます。**
> `VNA_CHANNEL_NAMES`（既定 `["leftbody", "rightbody"]`）で台数を決めます。コンバイナが「その時点で最も新しい各台の掃引」と OptiTrack の座標を 1 行に結合します。CSV 列は `leftbody_...` / `rightbody_...` で区別されます。掃引条件（開始/終了周波数・点数）は**全台共通**です。1 台のみでの運用や、片方だけテストモードにする運用も可能です。
>
> **【RF 干渉対策：交互計測】** 2 台を**同時に**掃引すると、両機が同じ周波数帯で同時に送信するため RF が干渉し、両方のインピーダンスに大きなノイズが乗ります。これを防ぐため、**既定では実機を 1 台ずつ順番に掃引します**（`VNA_ALTERNATE_SWEEP = True`）。掃引の合間に待ち時間は入れないため、各台の FPS は「同時掃引の約 1/実機台数」に収まります（＝2 台を同時に送信させないための物理的な下限）。並列同時掃引に戻すには `VNA_ALTERNATE_SWEEP = False`。
>
> **片方をテストモードにした場合**は、実機が 1 台だけになり RF 干渉が起きないため、**その 1 台を全速で掃引**します（交互待ちで FPS を落としません）。テストモード側の列はダミー 0 で埋められます。

> **【操作方法】GUI（tkinter）で計測します。**
> プログラムを実行すると操作画面が立ち上がります。**各 VNA の COM ポートを選択 → ［計測開始］→ ［計測終了 / 保存］** の流れで操作し、終了時にファイル保存ダイアログで保存先を指定します。計測・通信はバックグラウンドスレッドで動くため GUI は固まりません。終了時（終了ボタン／ウィンドウ×／プロセス終了のいずれでも）に、**全 VNA のクローズ・NatNet の切断・全スレッドの join を必ず実行**してリソース（COM ポート・UDP ソケット）を確実に解放します。これにより「2 回目以降の起動でフリーズする」問題を防ぎます。
>
> 計測する S パラメータは **S11 固定**です。

> **【VNA 接続：COM ポートの動的選択】画面で各 VNA の接続先 COM ポートを選べます。**
> GUI の VNA チャンネルごとの「COM」ドロップダウンが、PC が認識しているシリアルポートを自動でリストアップします。VNA を後から挿した場合は **［ポート再検索］** ボタンで全チャンネルの一覧を更新できます（再起動不要）。［計測開始］時に選択された COM ポートが開けない（存在しない／他ソフトが占有／2 台が同じポート）場合は、**クラッシュせず警告ポップアップ**（`messagebox.showerror`）を表示し、再選択して再開できます。

> **【VNAなしテストモード】VNA 実機が無くても OptiTrack 単体で動作確認できます。**
> COM ポートの一覧末尾にある **「None（VNAなしテストモード）」** を（チャンネルごとに）選んで［計測開始］すると、その台は**接続・初期化を完全にスキップ**（接続エラーも出さない）します。全チャンネルをテストモードにすれば OptiTrack の座標だけをリアルタイム取得できます。テストモードの台の VNA 列（`VNA*_S11_Real, ...`）には **ダミー値 0** が入ります。終了・CSV 保存の流れは通常モードと同一です。

> **【掃引条件の自由設定】開始/終了周波数・点数を GUI から変更できます。**
> GUI の入力欄で **開始周波数[MHz]・終了周波数[MHz]・点数** を指定し［計測開始］を押すと、その条件が VNA に設定（`sweep`/`scan` コマンド）されてから計測が始まります。点数は **スピンボックスで 1 点刻みに増減（直接入力も可）** でき、任意の値（例: 55, 101, 102 …）を指定できます。**CSV のヘッダー（列名）とグラフ横軸も、指定した点数・周波数に応じてループで完全動的に生成**されます。

> **【サンプリングレート（FPS）モニタ】実測の取得レートを確認できます。**
> 計測中、GUI に **OptiTrack（受信フレーム）／ 各 VNA（取得掃引）の実測 FPS** が約 1 秒ごとに表示されます（例: `OptiTrack: 120.5 / leftbody: 22.1 / rightbody: 21.8 FPS`）。コンソールの 1 行カウンタにも同じ FPS が表示され、計測終了・CSV 保存時には**チャンネル別の平均 FPS サマリー**が出力されます。パフォーマンス分析・ボトルネック把握に利用できます（記録される行のペースは最も遅い VNA に律速されます）。

## 1. システム構成・動作環境

### 1.1 概要

本システムは、**1 台の Windows PC（ThinkPad）内で完結する**ことを最大の特徴とします。モーションキャプチャ用の PC と計測用の PC を分離せず、Motive・Python スクリプト・VNA 制御のすべてを同一マシン上で動作させることで、ネットワーク遅延や時刻同期のずれを最小化し、配線をシンプルに保ちます。

```
┌──────────────────────────────────────────────────────────────┐
│                  Windows PC (ThinkPad)                        │
│                                                              │
│   ┌────────────────┐         NatNet (UDP)                    │
│   │  Motive        │  ───────────────────────────┐           │
│   │  (OptiTrack)   │   127.0.0.1 (loopback)       │           │
│   └────────────────┘                              ▼           │
│         ▲                            ┌──────────────────────┐ │
│         │ 光学トラッキング            │  Python 同期計測       │ │
│         │                            │  スクリプト            │ │
│   （カメラ群）                        │  ・NatNetClient (受信) │ │
│                                      │  ・ラベルで座標取得    │ │
│                                      │  ・pyserial (VNA制御)  │ │
│   ┌────────────────┐   USB           │  ・各VNAを並行掃引     │ │
│   │ JNCRadio VNA 3G│ ◀──(COMポート)──▶│    (リーダースレッド)  │ │
│   │  #1 PORT1 = S11│                  │  ・threading.Lock      │ │
│   ├────────────────┤   USB            │    で同期・結合        │ │
│   │ JNCRadio VNA 3G│ ◀──(COMポート)──▶│                       │ │
│   │  #2 PORT1 = S11│   115200 bps     └──────────┬───────────┘ │
│   └────────────────┘                            │             │
│         ▲                                        ▼             │
│   （メアンダコイル服 ×2 = DUT）           sync_dataset.csv       │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 必要なハードウェア

| 機器 | 役割 | 備考 |
|------|------|------|
| **Windows PC（ThinkPad）** | Motive と Python スクリプトを同時実行する計測ホスト | 後述の通り高負荷になるため、できる限り高性能な機体を推奨 |
| **OptiTrack システム（カメラ群 + Motive）** | 身体に取り付けた 7 個のラベル付きマーカーの 3 次元位置をリアルタイム取得 | Motive のライセンスおよびキャリブレーション済みのキャプチャ空間が必要。マーカーのラベリング（マーカーセット）が必要 |
| **JNCRadio VNA 3G ×2** | 12.5–14.5 MHz を掃引して S11（反射係数）を測定 | **2 台**を別々の USB ポートに接続し、それぞれ別の対象を同時計測（各台が別の仮想 COM ポートとして認識される）。1 台のみでの運用も可 |
| **メアンダコイル服（DUT）** | 被測定物 | 各 VNA の **PORT1**（S11 測定ポート）に接続。左右の前腕・関節・上腕と胸に各 1 個、計 7 個の反射マーカーを貼付 |
| **ウェブカメラ（任意）** | 動きの様子を動画で記録し、計測中はライブ表示、後から時刻でデータと同期 | **［計測開始］と連動してこのシステムが OpenCV で録画**（要 `opencv-python`）。計測中は別ウィンドウにライブ表示。CSV の絶対時刻 `WallClock` と突き合わせて同期。→ [5.4](#54-カメラ録画とライブ表示計測と連動) |

### 1.3 ソフトウェア動作環境

- **OS:** Windows 10 / 11
- **Python:** 3.8 以上（64bit 推奨）
- **Motive:** OptiTrack 純正ソフトウェア（Data Streaming 対応バージョン。NatNet 4.x / Motive 3.1 系で動作確認）
- **NatNet SDK:** OptiTrack 公式 SDK（`NatNetClient.py` を使用）

## 2. セットアップ（環境構築）

### 2.1 Python ライブラリのインストール

コマンドプロンプト（または PowerShell）で以下を実行してください。

```bash
pip install pyserial scikit-rf matplotlib numpy pandas opencv-python
```

| ライブラリ | 用途 |
|-----------|------|
| `pyserial` | JNCRadio VNA 3G とのシリアル（COM ポート）通信 |
| `scikit-rf`（skrf） | **必須**。掃引した S11 をインピーダンス Z11 に変換 |
| `matplotlib` | **必須**。GUI 内のリアルタイムグラフ描画 |
| `numpy` | **必須**。配列演算（skrf/matplotlib の依存でもある） |
| `pandas` | 取得後のデータセットの読み込み・解析（後処理用、計測本体には任意） |
| `opencv-python`（cv2） | **カメラ録画・ライブ映像・フレーム抽出に必要**（[5.4](#54-カメラ録画とライブ表示計測と連動)）。カメラを使わない計測では不要 |

> **補足:** 計測本体の動作には `pyserial` / `scikit-rf` / `matplotlib` / `numpy` が必要です（`scikit-rf` をインストールすると `numpy` / `scipy` / `matplotlib` も併せて入ります）。`pandas` は取得済み CSV の後処理用で任意です。`opencv-python` は webカメラの録画・ライブ映像表示・フレーム抽出に使います（未導入ならカメラ機能だけがスキップされ、計測自体は動きます）。
> GUI に使う `tkinter` は **Python 標準ライブラリ**のため追加インストールは不要です（Windows の公式インストーラには標準で含まれます。最小構成等で `import tkinter` に失敗する場合のみ、Python を「tcl/tk」付きで入れ直してください）。

### 2.2 `NatNetClient.py` の配置（重要）

OptiTrack との通信には、OptiTrack が公式に配布する **NatNet SDK 同梱の Python サンプル `NatNetClient.py`** を使用します。これは `pip` では入手できません。本スクリプトは以下の **2 箇所のいずれか**に SDK ファイルがあれば自動で読み込みます（`sys.path` に自動追加）。

- **(A) 同梱 SDK をそのまま使う場合:** リポジトリ内の `./NatNetSDK/Samples/PythonClient/` に `NatNetClient.py` 等が置かれていれば、追加作業は不要です。
- **(B) 手動配置する場合:** OptiTrack 公式サイト（または Motive インストールフォルダ）から **NatNet SDK** を入手し、以下のファイルを **本体スクリプトと同じフォルダ**にコピーします。
  - `NatNetClient.py`（必須）
  - `MoCapData.py`（**必須**。フレームデータ（Rigid Body / Labeled Marker）の構造を解釈するために使用します）
  - `DataDescriptions.py`（**必須**。`NatNetClient.py` が内部で import します）

想定するフォルダ構成は以下のいずれかです。

```
# (A) 同梱 SDK 構成（このリポジトリの構成）
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── README.md
└── NatNetSDK/
    └── Samples/
        └── PythonClient/
            ├── NatNetClient.py
            ├── MoCapData.py
            └── DataDescriptions.py

# (B) 手動配置構成
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── NatNetClient.py
├── MoCapData.py
├── DataDescriptions.py
└── README.md
```

> **対応バージョン:** 本スクリプトは **NatNet 4.x（Motive 3.1 系）** の `NatNetClient.py` に合わせて実装しています。フレーム受信には `new_frame_with_data_listener`（`data_dict["mocap_data"]` に `MoCapData` を渡す）を使用します。

## 3. 事前設定の手順

計測を開始する前に、Motive 側と JNCRadio VNA 3G 側の双方で設定を済ませておく必要があります。

### 3.1 Motive（OptiTrack）側の設定

Motive を起動し、キャプチャ空間のキャリブレーションを済ませたうえで、**マーカーのラベリング**と **Data Streaming** パネルを設定します。

#### (a) 7 個のラベル付きマーカーの準備【最重要】

本システムは **ラベル付きマーカーの `marker_id`（アセット内の 1 始まりの番号）でマーカーを識別**します。Motive 側で以下を満たしてください。

1. 左右の前腕・関節・上腕と胸のそれぞれに反射マーカーを **1 個ずつ（計 7 個）** 取り付けます。
2. Motive 上で 7 個のマーカーをラベリングし、**ラベル付きアセット**（またはマーカーセット）として配信できる状態にします。ラベル名の例: `R_forearm, R_joint, R_upperarm, chest, L_forearm, L_joint, L_upperarm`。
3. **`marker_id` の並びを控えておきます。** フレームデータにマーカー名は含まれず、位置は `marker_id`（1, 2, 3, …）付きで届きます。スクリプトの `EXPECTED_MARKER_NAMES` に `marker_id` の順（`marker_id=1` → 先頭）で名前を記述します（実際の対応は起動直後の診断ログで確認可能。§6 参照）。
4. マーカーが隠れる（オクルージョン）とそのマーカーは occluded フラグ付き、または一覧から消える／`(0,0,0)` で配信されるため、本システムはそのサンプルを破棄します。**7 個すべてがカメラから安定して見える**配置・姿勢で計測してください。

> **ラベリングが必要です。** 高さによる自動判別は廃止したため、Motive 側でマーカーをラベル付けし、アセット（またはマーカーセット）として配信する設定が前提になります。

#### (b) Data Streaming の設定

1. メニューから **Data Streaming** パネルを開きます。
2. **Broadcast Frame Data** を **ON（有効）** にします。
3. **Local Interface** を **`127.0.0.1`（localhost / loopback）** に設定します。
   - 同一 PC 内でデータを受け渡すため、外部ネットワークではなくループバックアドレスを指定するのが要点です。
4. **Transmission Type** を **Unicast** に設定します。
   - 同一 PC 内のループバック通信では Multicast よりも Unicast の方が安定します。本スクリプトも Unicast 前提（`set_use_multicast(False)`）で実装されています。
5. **Labeled Markers**（ラベル付きマーカー）の配信を **ON** にします（マーカーセットを使う場合は **Markers** も ON）。
   - これが無効だとマーカーの座標が配信されず、位置を取得できません。

> **座標系について:** 本スクリプトは Motive の配信座標系の値をそのまま記録します（Y-Up / Z-Up のいずれでもそのまま保存）。解析時は Motive 側の座標系設定に合わせて軸の向きを解釈してください。

### 3.2 JNCRadio VNA 3G 側の設定

#### (a) COM ポート番号の確認

1. USB Type-C ケーブルで JNCRadio VNA 3G を PC に接続します。
2. **デバイスマネージャー** を開きます（`Win + X` → 「デバイス マネージャー」）。
3. **「ポート (COM と LPT)」** の項目を展開します。
4. 接続した VNA に対応する仮想シリアルポート（例: `USB Serial Device (COM3)`）を確認し、**COM 番号**を控えます。
   - 接続前後でデバイスマネージャーを見比べると、新たに増えたポートが VNA に対応するものです。
   - この COM 番号を後述の `NANOVNA_PORT` に設定します。

> JNCRadio VNA 3G のシリアルボーレートは適応式ですが、本体・スクリプトともに **115200 bps** を使用します（マニュアル §7 準拠）。

#### (b) キャリブレーション（SOLT）の事前実施【強く推奨】

S11 を正確に測定するため、**計測を開始する前に本体側で校正（キャリブレーション）を済ませておくこと**を強く推奨します。

1. メアンダコイル服を接続する **PORT1（S11 測定ポート）** に対して、付属の校正キットを用いて **SOLT 校正** を行います。
   - **S** = Short（短絡）
   - **O** = Open（開放）
   - **L** = Load（50 Ω 終端負荷）
   - **T** = Through（PORT1–PORT2 間。S11 のみであれば省略可）
2. マニュアル §4.4 / §7.2.14（`cal` コマンド）の手順に従い、各標準器を接続して校正を実施します。校正後は必ず校正データを保存（`save {id}` または本体メニュー）してください。
3. 掃引範囲（12.5–14.5 MHz）全体を含む周波数範囲で校正されていることを確認します。

> **重要:** 未校正のまま測定すると S11 が不正確になり、後段で算出されるインピーダンス Z も信頼できない値になります。データセットの品質を担保するため、校正は必ず実施してください。

> **校正について:** 本システムは **S11（PORT1 の反射）固定**で計測します。PORT1 の反射校正（最低でも Open / Short / Load）を実施し、被測定物（メアンダコイル服）を PORT1 に接続してください。

## 4. 使い方（実行手順）

### 4.1 スクリプト内変数の書き換え

`sync_optitrack_nanovna.py` の冒頭にある **設定ブロック**を、ご自身の環境に合わせて編集します。

```python
# --- NanoVNA / JNCRadio VNA-3G (シリアル) ---
NANOVNA_PORT   = "COM3"        # GUI の COM ポート一覧の「初期選択候補」（実際は画面で選択）
NANOVNA_BAUD   = 115200        # ボーレート（通常は変更不要）
Z0             = 50.0          # 特性インピーダンス [Ω]（通常は 50）

# --- VNA チャンネル（複数台の計測） ---
# 列挙した名前ぶんだけ COM ポート選択欄が GUI に並ぶ。
# CSV 列は leftbody_..., rightbody_... のようにチャンネル名で区別されるので、
# 保存データからどちらの対象のインピーダンスかを判別できる。1 台なら ["leftbody"]。
VNA_CHANNEL_NAMES = ["leftbody", "rightbody"]

# 交互計測（RF 干渉対策）。True で 1 台ずつ順番に掃引（2 台同時送信によるノイズを防ぐ）。
# False で並列同時掃引（高速だが 2 台同時だと干渉しうる）。
VNA_ALTERNATE_SWEEP = True

# --- 掃引（スイープ）条件の既定値（実際の値は GUI で指定する） ---
# 開始/終了周波数・点数は GUI 入力欄の初期値。[計測開始]時に画面の値が採用される。
SWEEP_START_HZ = 12_500_000    # 掃引開始 [Hz]（12.5 MHz）= GUI 初期値
SWEEP_STOP_HZ  = 14_500_000    # 掃引終了 [Hz]（14.5 MHz）= GUI 初期値
SCAN_POINTS    = 101           # 掃引点数 = GUI 初期値
POINTS_MIN = 2                 # 点数スピンボックスの最小（1 刻みで任意指定可）
POINTS_MAX = 100_000           # 点数スピンボックスの上限
TARGET_FREQ_HZ = 13_560_000    # 参考: グラフの縦線マーカー（13.56 MHz）

# --- 計測する S パラメータ（S11 固定） ---
# scan の outmask: bit0(=1)=周波数, bit1(=2)=S11 →「周波数+S11」(=3) を出力させる。
VNA_SPARAM  = "S11"
VNA_OUTMASK = 2

# --- OptiTrack (NatNet) ---
NATNET_SERVER_IP = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_LOCAL_IP  = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_USE_MULTICAST = False    # 同一PCループバックは Unicast 推奨（通常は変更不要）

# --- マーカーの識別（ラベル認識）方式 ---
# marker_id（アセット内の 1 始まりの番号）の並びと同じ順序でラベル名を列挙する。
# marker_id=i のマーカー -> EXPECTED_MARKER_NAMES[i-1]。CSV の位置列もこの順序。
# 実際の対応は起動直後の診断ログ（MARKER_DIAGNOSTIC_FRAMES）で確認して合わせる。
EXPECTED_MARKER_NAMES = [
    "R_forearm", "R_joint", "R_upperarm",
    "chest",
    "L_forearm", "L_joint", "L_upperarm",
]
# 座標取得のソース: "labeled_marker"（marker_id で対応付け）/ "marker_set"（セット内の並び順）
MARKER_SOURCE = "labeled_marker"
# labeled_marker のとき対象アセットの model_id（None なら marker_id が範囲内の全て）。
# 余計なラベル付きマーカーが混じる場合は診断ログの model= の値を指定する。
MARKER_MODEL_ID = None
# marker_set のとき使うマーカーセット名（"" でマーカー数が一致するセットを自動採用。"all" 除外）。
MARKER_SET_NAME = ""
# オクルージョン判定: 原点近傍（各軸の絶対値がこの値以内）を「未認識」とみなす。NaN も未認識。
OCCLUSION_ORIGIN_EPS = 1e-6
# 起動直後に受信フレームの構造をログ出力する回数（0 で無効）。並び順・形式の確認に使う。
MARKER_DIAGNOSTIC_FRAMES = 5

# --- 出力 ---
OUTPUT_CSV = "sync_dataset.csv" # 保存ダイアログに出す初期ファイル名（実際の保存先は実行時に選択）
```

最低限、以下を環境に合わせて変更してください。

| 変数 | 設定内容 |
|------|---------|
| `VNA_CHANNEL_NAMES` | 計測する VNA のチャンネル名リスト（既定 `["leftbody", "rightbody"]`）。台数ぶんの COM 選択欄が GUI に並び、CSV 列は各名前で区別。1 台なら `["leftbody"]` |
| `VNA_ALTERNATE_SWEEP` | `True`（既定）で **1 台ずつ順番に掃引**（RF 干渉対策）。`False` で並列同時掃引（高速だが 2 台同時だと干渉しうる） |
| `NANOVNA_PORT` | COM ポート一覧の初期選択候補（実際の接続先は **GUI で各チャンネルごとに選択**するため必須ではない） |
| `SWEEP_START_HZ` / `SWEEP_STOP_HZ` / `SCAN_POINTS` | 掃引条件の **GUI 初期値**（全 VNA 共通。実際の値は画面の入力欄で指定。CSV 列数・グラフ点数は指定点数に追従） |
| `TARGET_FREQ_HZ` | グラフに引く参考縦線の周波数（既定 13.56 MHz） |
| `EXPECTED_MARKER_NAMES` | 計測対象マーカーの名前を **`marker_id` の並び**で列挙（`marker_id=i` → `[i-1]`）。CSV 位置列の順序も兼ねる |
| `MARKER_SOURCE` | 座標取得のソース。`"labeled_marker"`（既定）または `"marker_set"` |
| `MARKER_MODEL_ID` | `labeled_marker` で対象アセットを限定する model_id（`None` で無制限。診断ログの `model=` を指定） |
| `MARKER_SET_NAME` | `marker_set` 使用時のセット名（`""` で自動選択：マーカー数が一致するセット、`all` は除外） |
| `MARKER_DIAGNOSTIC_FRAMES` | 起動直後に受信構造をログ出力するフレーム数（並び順の確認用。不要なら `0`） |

> **COM ポートについて:** どの COM ポートに接続するかは **GUI のドロップダウン（VNA チャンネルごとに 1 つ）で選択**します（コード編集は不要）。2 台つないでいれば起動時に自動で leftbody=1 台目, rightbody=2 台目 が割り当てられます。`NANOVNA_PORT` は初期選択候補にすぎません。**同じ COM ポートを 2 チャンネルに割り当てると開始時にエラー**になります（各 VNA は別ポート）。

> **注意:** マーカーの識別は「`marker_id` の並び」に依存します（`marker_id=i` → `EXPECTED_MARKER_NAMES[i-1]`）。この順序が Motive の配信と食い違うと、名前と座標の対応がずれます。**初回は必ず起動直後の診断ログで各マーカーの座標を確認し、並びを合わせてください**（§6 参照）。

### 4.2 起動と GUI 操作

Motive を起動して Data Streaming を有効化し、VNA を USB 接続した状態で、以下を実行します。

```bash
python sync_optitrack_nanovna.py
```

実行すると **操作画面（GUI）** が立ち上がります。次の流れで操作します。

#### ステップ 0: 各 VNA の COM ポートを選ぶ

- 画面上部に **VNA チャンネルごとの COM ポート選択欄**（`leftbody COM:` / `rightbody COM:` …）が並びます。各欄で、その台が接続されている COM ポートを選択してください（例: `COM3 - USB Serial Device (COM3)`）。**2 台つないでいれば起動時に自動で leftbody=1 台目, rightbody=2 台目 が割り当てられます。**
- **各 VNA には別々の COM ポート**を割り当ててください。同じポートを 2 チャンネルに指定すると開始時にエラーになります。
- **VNA を後から挿した／一覧に出ない場合**は、**［ポート再検索］** ボタンを押すと全チャンネルの一覧が更新されます（プログラムの再起動は不要）。
- どの COM ポートか分からない場合は、VNA を抜き差しして増減するポートが目印です（デバイスマネージャーの「ポート (COM と LPT)」でも確認できます）。
- **その台の VNA 実機が無いとき**は、そのチャンネルで **「None（VNAなしテストモード）」** を選びます。その台はスキップされ、対応する VNA 列にはダミー値 0 が入ります（OptiTrack 受信・保存の動作確認用）。
- この選択は **［計測開始］を押した時点で確定**します。計測中は COM ポート変更・再検索はできません（停止後に再選択可能）。

#### ステップ 0.5: 掃引条件を設定する

- 「開始[MHz]」「終了[MHz]」「点数」の入力欄に、測定したいスイープ条件を入力します（初期値: 12.5 / 14.5 / 101）。**点数はスピンボックスで、上下の矢印で 1 点ずつ増減**できるほか、ボックスに任意の整数を直接入力できます（例: 55, 101, 102 …）。
- ［計測開始］を押すと、この値が VNA に設定（`sweep`/`scan` コマンド）されてから計測が始まります。**CSV のヘッダー（列名）とスミスチャートも、ここで指定した点数・周波数と VNA 台数に応じて自動生成**されます。掃引条件は **全 VNA 共通**です。
- **「読み取り周波数[MHz]」** 欄には、スミスチャートの数値表示に使う周波数を入力します（初期値 13.56）。この値に最も近い掃引点のインピーダンス Z = R + jX が各 body について数値表示されます。**この欄は計測中でも変更でき**、次の更新から反映されます（§5.3）。
- 入力が不正（開始≧終了、数値でない、点数が範囲外）の場合は警告が出て計測は始まりません。計測中はこれらの掃引入力欄は変更できません（読み取り周波数を除く。停止後に再編集可能）。
- **点数を増やすほど周波数分解能は上がりますが、1 掃引の所要時間が延びて各 VNA の FPS（同期レート）は下がります**（§4.2 のFPS表示で実測を確認できます）。

#### ステップ 0.7: 計測モードを選ぶ（OptiTrack / カメラ同期）

- **「OptiTrack を使う」**（既定 ON）: OFF にすると NatNet を使わず **VNA のみ**計測します（Motive 未接続でも可。座標列は空欄）。
- **「カメラ撮影と同期する」**（既定 ON）: ON にすると **［計測開始］と連動して webカメラ録画**が始まり、CSV に `WallClock` 列＋保存時に `meta.json`＋動画（CSV の隣に `WIN_..._Pro.mp4`）が出力されます。**「カメラ番号」**（既定 0）で使用カメラを選べます。OFF なら従来形式（録画・`WallClock` 列なし）。
- **「計測中にライブ表示を開く」**（既定 ON）: 別ウィンドウで 3D マーカー／肘角度／スミス／カメラ映像をライブ表示します（掃引レート非依存で更新）。詳しくは [5.4](#54-カメラ録画とライブ表示計測と連動)。
- 画面右下の **「現在時刻」** 表示は、動画と共有する時刻軸（＝`WallClock` の基準）です。
- これらのチェックは **［計測開始］時に確定**し、計測中は変更できません（停止後に再選択可能）。

#### ステップ 1: ［計測開始］を押す

- 計測（データ取得）がバックグラウンドで開始します。
- このとき **起動直後の数フレーム**、受信フレームの構造（マーカーセット名・個数・各インデックスの座標）が GUI ログに出力されます（`MARKER_DIAGNOSTIC_FRAMES`）。**初回は必ずこのログで並び順を確認し、`EXPECTED_MARKER_NAMES` と一致しているかチェック**してください（§6 参照）。
- 以降は、**7 個のマーカーがすべて認識できているサンプルだけ**が記録され、1 個でも未認識（オクルージョン等）のフレームは自動破棄されます（ログに `マーカー未認識のためサンプルを破棄: ...` と表示）。
- 画面の「状態」「サンプル数」「取得レート（FPS）」とログ欄で進行状況を確認できます。**取得レート**は約 1 秒ごとに更新され、`OptiTrack: 120.5 / leftbody: 22.1 / rightbody: 21.8 FPS` のように **OptiTrack（受信フレーム数）と各 VNA（取得掃引数）の実測 FPS** を個別表示します。**詳細な進行ログは GUI のログ欄に集約**され、コンソール（PowerShell）には重要イベントと 1 行の進捗カウンタのみが出ます。

#### ステップ 2: ［計測終了 / 保存］を押す

- 計測を停止し、内部に溜めていたデータを書き出す準備をします。
- 直後に **ファイル保存ダイアログ**（`tkinter.filedialog.asksaveasfilename`）が表示されるので、**保存先フォルダと CSV ファイル名**を指定します。
- ファイル名を決定すると CSV が保存され、保存完了のメッセージののち **GUI が安全に閉じてプログラムが終了**します。
- 保存完了時に、**計測全体の平均 FPS サマリー**（計測時間／OptiTrack 平均 FPS／各 VNA 平均 FPS）が GUI ログ欄とコンソールの両方に出力されます。
- 保存をキャンセルした場合はデータ破棄の確認が出ます（破棄して終了するか、保存ダイアログをやり直すか選べます）。

> **データの保持方式:** 計測中のデータは**メモリ上に蓄積**され、終了時にまとめて 1 つの CSV に書き出します。途中経過を逐次ファイルに書く方式ではないため、保存はステップ 2 で必ず行ってください（長時間計測でメモリ使用が気になる場合はご相談ください）。

### 4.3 終了とクリーンアップ（重要）

終了の方法は次の 3 通りで、**いずれの場合も** VNA のクローズ・NatNet の切断・全スレッドの join を確実に実行してから終了します。

1. **［計測終了 / 保存］ボタン** … 推奨。保存ダイアログ → CSV 保存 → 終了。
2. **ウィンドウの ×（閉じる）** … 計測中なら確認のうえ停止・クリーンアップし、保存ダイアログを表示してから終了します。
3. **致命的エラー時**（VNA 切断など）… エラーを通知して計測を畳み、再度［計測開始］できる状態に戻します。

クリーンアップでは以下を順に実施します。

1. 計測ワーカースレッドへ停止を要求し、`join` で終了を待つ。
2. VNA に `resume` を送って掃引表示を元に戻し、シリアルポート（COM ポート）を閉じる。
3. NatNet クライアントを `shutdown()` し、受信スレッドと UDP ソケットを解放する。

> **【バグ修正】2 回目以降の起動でフリーズしないために。**
> これらの解放処理を「終了経路すべてで・冪等に」行うことで、COM ポートや UDP ソケット、受信スレッドが確実に解放されます。以前発生していた「一度実行して終了したあと、次の実行で `Ctrl + C` を受け付けずフリーズする」問題は、この厳密なクリーンアップにより解消されています。GUI 運用のため計測の開始・停止はボタンで行い、`Ctrl + C` には依存しません。

## 5. 出力データ構造（CSV ヘッダー解説）

出力ファイル（終了時の保存ダイアログで指定。初期名: `sync_dataset.csv`）は、**1 行 = 位置情報（23 列※）＋ VNA チャンネル数 × 掃引データ（点数 N × 4 列）**のワイド形式 CSV です（カメラ同期 ON・VNA 2 台・N=101 なら 23 + 2×404 = 831 列）。**列数・列名は［計測開始］時に指定した点数・周波数と VNA 台数に応じて動的に生成**されます。位置データは **7 マーカー × (X, Y, Z) = 21 値**（列順は `EXPECTED_MARKER_NAMES` の順）で、各座標は対応するマーカーの中心座標（Motive の配信座標系、単位はメートル）です。掃引データは **leftbody の全点 → rightbody の全点**の順に、各列名の先頭にチャンネル名（`leftbody_` / `rightbody_`）が付きます。

> ※ **絶対時刻列 `WallClock` は GUI の「カメラ撮影と同期する」チェックで切り替わります。** ON のとき `Timestamp` の次に `WallClock`（絶対時刻・ローカル・ミリ秒精度）が入り、位置情報は 23 列になります（ウェブカメラ動画との時刻同期用の「共有時刻軸」）。このとき保存時に CSV の隣へ `<csv名>.meta.json`（計測開始/終了の絶対時刻など）と、連動録画した動画 `WIN_..._Pro.mp4` も自動生成されます。**OFF のときは `WallClock` 列も `meta.json` も出力されず**、位置情報は従来どおり 22 列（`Timestamp` + 21 値）になります。詳しくは [5.4 カメラ録画とライブ表示](#54-カメラ録画とライブ表示計測と連動) を参照してください。

> **座標系について:** 本システムは Motive で設定された配信座標系の値をそのまま記録します。NatNet の既定は **Y-Up**（Y 軸が鉛直上向き）ですが、Motive の設定により **Z-Up** に変更されている場合もあります。解析時は Motive 側の座標系設定に合わせて軸の向きを解釈してください。

**先頭 22〜23 列（位置情報）** — `Timestamp`（カメラ同期 ON なら続いて `WallClock`）に続いて、各マーカーの X/Y/Z が `EXPECTED_MARKER_NAMES` の順に並びます。

| カラム名 | 意味 | 単位 |
|----------|------|------|
| `Timestamp` | 各サンプルの計測開始からの経過時間（`perf_counter` 基準、ミリ秒精度） | 秒 [s] |
| `WallClock` | 各サンプルの**絶対時刻**（ローカル時刻・ミリ秒精度 `YYYY-MM-DD HH:MM:SS.fff`）。動画同期の基準。`WallClock = 計測開始の壁時計 + Timestamp`。**「カメラ撮影と同期する」ON のときのみ**の列 | 時刻 |
| `R_forearm_X/Y/Z` | **右前腕**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `R_joint_X/Y/Z` | **右関節**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `R_upperarm_X/Y/Z` | **右上腕**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `chest_X/Y/Z` | **胸**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `L_forearm_X/Y/Z` | **左前腕**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `L_joint_X/Y/Z` | **左関節**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |
| `L_upperarm_X/Y/Z` | **左上腕**マーカーの X/Y/Z 座標（Motive 座標系） | メートル [m] |

**以降の列（掃引データ）** — チャンネルごと（`leftbody` → `rightbody`）に、掃引周波数ごとの 4 列が **開始周波数から終了周波数まで指定点数分**繰り返されます（列名は `<チャンネル>_<項目>_<MHz>`。例は 12.5–14.5 MHz / 101 点の場合）。

| カラム名（例: leftbody / 12.5 MHz） | 意味 | 単位 |
|----------|------|------|
| `leftbody_S11_Real_12.5` | その周波数の反射係数 S11 の**実部** | 無次元（線形） |
| `leftbody_S11_Imag_12.5` | その周波数の反射係数 S11 の**虚部** | 無次元（線形） |
| `leftbody_Z_R_12.5` | `scikit-rf` で換算した複素インピーダンス Z11 の**実部（抵抗 R）** | オーム [Ω] |
| `leftbody_Z_X_12.5` | `scikit-rf` で換算した複素インピーダンス Z11 の**虚部（リアクタンス X）** | オーム [Ω] |
| …（次の周波数 `12.52`, `12.54`, … 終了周波数まで） → 続けて `rightbody_S11_Real_12.5` …（rightbody の全点） | | |

> 単一周波数（1 点）モードでは MHz サフィックスを省き、`leftbody_S11_Real` / `leftbody_Z_R` … のようになります。

> **マーカー未認識時:** 7 マーカーのいずれかが未認識（オクルージョン等）のフレームは、そのサンプル自体が CSV に記録されず破棄されます。したがって記録された行は常に 7 マーカーすべての座標が揃っています（位置セルが空欄の行は生じません）。その分、消失していた期間のサンプルは間引かれ、`Timestamp` の間隔が飛びます。

> **VNAなしテストモードの場合:** 掃引データ列（点数 × 4 列）すべてにダミー値 `0` が入ります（OptiTrack の座標列は通常どおり記録されます）。

### 5.1 同期の仕組み

OptiTrack の更新レート（数百 Hz）と VNA の掃引取得レート（1 掃引あたり数十〜数百 ms）には大きな差があります。本システムは次のスレッドで構成されます。

- **NatNet 受信スレッド**: フレームのたびに `marker_id` → ラベル名の対応で 7 マーカーの座標を `threading.Lock()` 下で更新し続けます（未認識のマーカーは無効化）。
- **VNA リーダー**: 各 nanoVNA を掃引し、最新の掃引結果（S11 → Z11）を自分のスロットへ publish します。
  - **交互モード（既定, `VNA_ALTERNATE_SWEEP = True`）**: **1 本のスレッド**が **実機のチャンネルだけ**を **1 台ずつ順番に**掃引します。同時に 2 台が送信しないため RF 干渉によるノイズを防ぎます。掃引の合間に待ち時間は入れないので、FPS の低下は「同時掃引の約 1/実機台数」に収まります（＝物理的な下限）。**テストモードのチャンネルは掃引せず**、実機の掃引ごとにダミー 0 を埋めるだけなので、**実機が 1 台だけのときはその 1 台を全速で掃引**でき、交互待ちで FPS を損ないません。
  - **並列モード（`= False`）**: **チャンネルごとに専用スレッド**で同時掃引します（高速だが、2 台が同じ帯域で同時に送信するため干渉しうる）。
- **コンバイナスレッド**: **全チャンネルが「前回消費より新しい掃引」を出す**のを待ち、その瞬間に 7 マーカーの最新座標を一括スナップショットして、各 VNA の最新掃引と結合し 1 行にします。**1 個でも未認識のマーカーがあればその行は破棄**し、全マーカーが揃っている場合のみ蓄積します。

すなわち CSV の 1 行は、「その時点で最も新しい各 VNA の掃引（S11/Z）」と「7 マーカー（計 21 値）の位置」をまとめたものです。行のペースは**最も遅い VNA**に律速されます（交互モードでは 1 巡ぶんで 1 行）。

ロックは 7 マーカーまとめて取得する間だけ保持されるため、行内でマーカーごとに時刻がずれることはありません。GUI（メインスレッド）・リーダー・コンバイナ・NatNet 受信スレッドは分離されているため、計測中も画面操作が固まりません。

> **掃引条件は全 VNA 共通**です（開始/終了周波数・点数）。別々の周波数範囲で計測したい場合は拡張が必要です。リアルタイム表示は **leftbody / rightbody の両方**をスミスチャートで並べて表示します（CSV には全チャンネルが記録されます）。

### 5.2 インピーダンスへの変換（scikit-rf）

掃引した点数分の複素 S11 を `scikit-rf` の `Network` オブジェクトに変換し、特性インピーダンス **Z₀ = 50 Ω** 基準でインピーダンス **Z11** を求めて `Z_R`・`Z_X` に記録します。

```python
import skrf as rf, numpy as np
s = np.asarray(s11_array, dtype=complex).reshape(-1, 1, 1)   # (N, 1, 1)
freq = rf.Frequency.from_f(freq_grid_hz, unit="Hz")          # 指定した周波数グリッド
ntwk = rf.Network(frequency=freq, s=s, z0=50)
z11 = ntwk.z[:, 0, 0]          # 各周波数の複素インピーダンス
Z_R, Z_X = z11.real, z11.imag  # 実部(抵抗) / 虚部(リアクタンス)
```

数式的には反射係数から `Z = Z0 × (1 + S11) / (1 − S11)` を全点に適用したものです。生の S11 と換算後の Z の双方を保存しているため、後処理で別の Z₀ を用いた再計算や、S11 ベースの解析（リターンロス・VSWR 等）も柔軟に行えます。

### 5.3 リアルタイム表示（スミスチャート ＋ 数値読み取り）

計測中、GUI 内に **leftbody / rightbody それぞれのスミスチャート**（matplotlib を tkinter に埋め込み。格子は `scikit-rf` で描画）が横並びで表示されます。

- 各チャートは、その台の掃引全点の **反射係数 Γ = S11**（Z0 = 50 Ω 基準）をスミスチャート上にプロットします。腕を動かすと Γ の軌跡がリアルタイム更新され、整合状態（中心＝整合、外周＝全反射）を視覚的に確認できます。
- チャート上の **★マーカー**は「読み取り周波数」に最も近い掃引点を示します。

**数値読み取り:** GUI の **「読み取り周波数[MHz]」** 欄に周波数を入力すると、その周波数に最も近い掃引点の **インピーダンス Z = R + jX**（および `|S11|` と実際の最近傍周波数）を、各 body について数値表示します。

```
leftbody:   Z = 64.23 + j18.24 Ω   |S11|=0.200   @ 13.5600 MHz
rightbody:  Z = 70.65 + j16.42 Ω   |S11|=0.100   @ 13.5600 MHz
```

- 読み取り周波数は **計測中でも変更でき、次の更新から反映**されます（掃引範囲外を入力した場合は範囲内の最近傍点にスナップします）。
- 単一周波数（1 点）モードでは、その 1 点が各チャートに 1 つの点として表示され、その値が数値表示されます。

> 描画は GUI のポーリング（約 10 fps）ごとに「その間に届いた最新の掃引 1 件」だけを反映する間引き方式のため、高速サンプリングでも GUI が重くなりません。VNAなしテストモードでは Γ=0（中心）に点が表示され、`Z = 50 + j0 Ω` になります。

### 5.4 カメラ録画とライブ表示（計測と連動）

**［計測開始］を押すと、連動して webカメラの録画が始まります。** 動画は OpenCV でこのシステムが直接録画し、計測終了・CSV 保存時に **CSV と同じフォルダへ `WIN_YYYYMMDD_HH_MM_SS_Pro.mp4`** として保存します。あわせて CSV に絶対時刻列 `WallClock` が付き、`meta.json` に録画開始時刻（`video_start_wall`）や動画ファイル名も残ります。

さらに、**計測中は別ウィンドウの「ライブ表示」ダッシュボード**が開き、`view_marker_impedances/viewer_3marker.py` と同じ内容（**3D マーカー＋ボーン／左右の肘角度（数値＋時系列）／左右 body の S11 スミスチャート／webカメラのライブ映像**）をリアルタイムに表示します。

> **【重要】表示は nanoVNA の掃引レートに律速されません。** ライブ表示は専用の高速タイマーで、その瞬間の**最新のマーカー座標・最新のカメラフレーム・各 VNA の最新掃引**を共有状態から直接読み取って描画します。CSV へ 1 行を確定する記録用ループ（全 VNA の新しい掃引が揃うまで待つ）とは独立して動くため、掃引が遅くても **OptiTrack 座標とカメラ映像はとぎれず**に更新されます（掃引が遅い分だけスミスチャートの更新が遅くなるだけです）。

> **低遅延描画（blit）:** 3D/スミス/角度の全体再描画は重い（〜0.24 秒）ため、通常は動くアーティスト（マーカー・ボーン・スミス曲線・カメラ映像）だけを **blit で部分描画**し、重い全体再描画は「3D 表示範囲の拡大・視点回転・リサイズ時のみ」に限定します。これによりカメラ映像とマーカーが**低遅延で滑らかに**（実測 ~18 fps・掃引律速時の数 fps から改善）更新されます。カメラ取得側もキャプチャスレッドが連続読み出しでバッファを消費するため、表示は常に最新フレームに近い状態になります。

**手順:**

1. GUI で **「カメラ撮影と同期する」にチェック**（既定 ON）、必要なら **「カメラ番号」**（既定 0）を選びます。**「計測中にライブ表示を開く」**（既定 ON）でダッシュボードの表示可否を切り替えます。
2. **［計測開始］** → webカメラ録画とライブ表示ウィンドウが自動的に始まります（GUI ログに録画開始が出ます）。
3. **［計測終了 / 保存］** → CSV を保存すると、その隣に動画 `WIN_..._Pro.mp4` も保存され、`meta.json` に動画情報が記録されます。ライブ表示ウィンドウは自動的に閉じます。

> - 動画の内部タイムラインが実時間とほぼ一致するよう、書き出し FPS は起動直後に実測した値を使います（取得できない環境では 30 fps）。
> - 「カメラ撮影と同期する」を OFF にすると録画・`WallClock` 列・`meta.json` は無効（従来形式）になります。ライブ表示の 3D / 角度 / スミスは、カメラ OFF でも（映像パネル無しで）表示できます。
> - OpenCV が未導入だと録画・映像パネルはスキップされます（`pip install opencv-python`）。カメラを別ソフト（Windows 標準カメラ等）で撮る運用も可能で、その場合も CSV の `WallClock` と動画ファイル名で後述の同期ができます。

**しくみ（後処理の突き合わせ）:**

```
video_time_sec = （データ行の WallClock） − （動画の録画開始時刻）
```

データ行 *i* は、動画の先頭から `video_time_sec[i]` 秒の位置に対応します。動画の録画開始時刻は、ファイル名 `WIN_YYYYMMDD_HH_MM_SS_Pro.mp4`（ローカル時刻・**秒**精度）から読み取ります。より厳密に合わせたい場合は、`meta.json` の `video_start_wall`（ミリ秒精度）を後処理スクリプトの `--video-start` に渡してください。

**後処理（対応付けスクリプト `sync_video_with_dataset.py`）:**

CSV の `WallClock` と動画の録画開始時刻を突き合わせ、各行に `video_time_sec`（動画の何秒目か）と `in_video`（動画範囲内か 1/0）を付けた同期済み CSV を出力します。**GUI（ファイル選択）と CLI の 2 通り**で使えます。

**GUI（パスをダイアログで選ぶ）** — 引数なしで起動、または `--gui`:

```bash
python sync_video_with_dataset.py
```

起動する小さなウィンドウで、**「参照…」ボタン**からデータセット CSV と動画ファイルのパスを選び（出力 CSV・録画開始時刻・フレーム抽出は任意）、**［同期実行］**を押します。進捗と結果はウィンドウ内のログに表示されます。

**CLI（コマンドライン）:**

```bash
# ファイル名から録画開始時刻を自動判定して同期 CSV を作る
python sync_video_with_dataset.py --csv sync_dataset.csv --video WIN_20260727_15_30_45_Pro.mp4
# → sync_dataset_video_synced.csv を出力
```

任意で、各データ行に対応する動画フレームを PNG で書き出せます（**ffmpeg が必要**）。

```bash
# 10 行ごとに対応フレームを frames/ へ書き出す
python sync_video_with_dataset.py --csv sync_dataset.csv --video clip.mp4 \
    --extract-frames frames --extract-every 10
```

主なオプション:

| オプション | 意味 |
|------------|------|
| `--csv` / `--video` | 入力 CSV / 動画ファイル（必須） |
| `--out` | 出力 CSV（既定: `<csv>_video_synced.csv`） |
| `--video-start "YYYY-MM-DD HH:MM:SS[.fff]"` | 録画開始時刻を明示指定（ファイル名を変えた場合など） |
| `--extract-frames DIR` / `--extract-every N` | 対応フレームを N 行ごとに PNG 出力（`ffmpeg` 必須） |
| `--ffmpeg` / `--ffprobe` | 実行パスを明示（PATH に無い場合） |

録画開始時刻の判定は **①`--video-start` → ②ファイル名 `WIN_...` → ③動画メタデータ `creation_time`（`ffprobe`。UTC はローカルへ変換）→ ④ファイル作成時刻**の順で自動選択されます。`ffmpeg`/`ffprobe` は任意で、無くてもファイル名から時刻を読めれば同期 CSV は作れます（動画長チェックとフレーム抽出のみ省略）。

> **精度について:** ファイル名の録画開始時刻は**秒精度**で、録画ボタンを押してから実際に最初のフレームが記録されるまでの遅延も乗りえます。そのため `video_time_sec` は**±1 秒程度の系統誤差**を含みえます。フレーム単位で厳密に合わせたい場合は、`--video-start` に手動で微調整した時刻を与えるか、動画内に映る時刻情報（GUI 右下の「現在時刻」など）を基準に補正してください。

### 5.5 取得済みデータ + 動画の再生ビューア（`playback_viewer.py`）

取得後の CSV とカメラ動画を**時刻同期して再生**するビューアです（`view_marker_impedances/viewer_3marker.py` を土台に、再生エンジンを作り替えたもの）。3D マーカー＋ボーン、左右の肘角度（数値＋時系列）、左右 body の S11 スミスチャート、動画パネルを 1 画面に表示し、Play/Pause・フレームスライダー・周波数スライダーで操作できます。

```bash
# 同期済み CSV(video_time_sec 付き) + 動画
python playback_viewer.py sync_dataset_video_synced.csv --video WIN_20260727_15_30_45_Pro.mp4

# 生の CSV(WallClock 付き) + 動画（video_time_sec はファイル名 WIN_… から内部計算）
python playback_viewer.py sync_dataset.csv --video WIN_20260727_15_30_45_Pro.mp4

# 動画なし（マーカー/スミスのみ再生）
python playback_viewer.py sync_dataset.csv
```

**再生時の同期の考え方（重要）:** マーカー座標とスミスチャートは「同じ CSV 行」から描くので常に同期します。動画は VNA（＝ CSV 行）より遥かに高 FPS のため、行ごとに動画をシークすると多数のフレームを飛ばして**とびとび**になります。これを避けるため、本ビューアは**動画フレームを順番に（飛ばさず）連続再生**し、その時刻に対応する CSV 行を `video_time_sec` から求めてマーカー/スミスを更新します。

- 動画パネル … 毎フレーム更新（`blit` で高速描画）。**飛ばさないので滑らか**。
- マーカー/スミス/肘角度 … 対応する CSV 行が変わったときだけ全体を再描画（VNA レートで段階的に切り替わる）。

`video_time_sec` 列（`sync_video_with_dataset.py` が付与）があればそれを使い、無い場合でも `WallClock` 列＋動画ファイル名 `WIN_YYYYMMDD_HH_MM_SS(_Pro).mp4`（または `--video-start`）から内部計算します。動画表示には `opencv-python` が必要です。

## 6. ラベル認識の仕組み（技術解説）

Motive が配信するフレームには**マーカー名は含まれません**。ラベル付きマーカーは **`marker_id`（アセット内の 1 始まりの番号、`id_num` の下位 16bit）** 付きで毎フレーム配信されます。本システムはこの **`marker_id` を `EXPECTED_MARKER_NAMES` に対応付け**て各マーカーの座標を取得します（既定 `MARKER_SOURCE = "labeled_marker"`）。処理の流れは次の通りです。

1. **ラベル付きマーカーの収集（毎フレーム）（`collect_named_markers()` → `_collect_from_labeled_markers()`）**
   フレーム内の各ラベル付きマーカーについて、`id_num` を `model_id`（上位 16bit）と `marker_id`（下位 16bit）に分解します。
   - `MARKER_MODEL_ID` が指定されていれば、その `model_id` 以外は無視します。
   - `marker_id = i` のマーカーを `EXPECTED_MARKER_NAMES[i-1]` に割り当てます。
   - occluded ビットが立っている／原点近傍（`OCCLUSION_ORIGIN_EPS` 以内）／NaN のマーカーは「未認識」として除外します。
   - （`MARKER_SOURCE = "marker_set"` の場合は、代わりにマーカーセット内の並び順で対応付けます。）

2. **最新座標の更新（毎フレーム）**
   認識できたマーカーは最新座標 (X, Y, Z) を `valid=True` で更新し、認識できなかったマーカーは `valid=False` に戻します（古い座標を保持し続けないため）。

3. **サンプルの採否（掃引ごと）**
   VNA の 1 掃引が終わるたびに 7 マーカーの `valid` を確認し、**全て `valid` の場合のみ 1 行として記録**します。1 個でも未認識ならそのサンプルは破棄します。

なお、起動直後の数フレーム（`MARKER_DIAGNOSTIC_FRAMES`）は、受信フレームの構造（マーカーセット、ラベル付きマーカーの `marker_id`／`model_id`／座標、リジッドボディ、名前解決結果）を GUI ログへ出力します。**初回はこのログで `marker_id` と部位の対応を確認し、`EXPECTED_MARKER_NAMES` の並びを実際の配信に合わせてください。**

## 7. 注意事項・トラブルシューティング

### 7.1 マーカーが認識されない / サンプルが記録されない場合

［計測開始］後に「マーカー未認識のためサンプルを破棄」が出続ける、サンプル数が増えない、または座標が取得できない場合は、まず**起動直後の診断ログ**を確認したうえで、以下をチェックしてください。

- **診断ログにラベル付きマーカーが 7 個出ているか。** `LabeledMarker 数: 0` の場合、Motive の Data Streaming で **Labeled Markers が OFF**、またはマーカーがラベリングされていません。Motive 側でラベリングと配信を有効にしてください。
- **`marker_id` が 1〜7 に収まっているか。** 診断ログの各マーカーの `marker=` を確認します。1 始まりでない／範囲外の場合は対応付けできません。余計なラベル付きマーカー（別アセット・点群）が混じっているときは、`MARKER_MODEL_ID` に対象アセットの `model=` の値を指定して限定してください。
- **`marker_id` と部位の対応が `EXPECTED_MARKER_NAMES` と一致しているか。** 診断ログの各マーカーの座標と実際のマーカー位置を突き合わせます。ずれていれば `EXPECTED_MARKER_NAMES` を並べ替えてください（対応がずれると、破棄はされなくても中身が入れ替わります）。
- **7 個すべてが同時に見えているか。** いずれかが隠れると occluded 扱い（または一覧から消える／`(0,0,0)`）になり、そのフレームのサンプルは破棄されます。診断ログの `→ 未解決/未認識: [...]` を確認し、カメラ配置・マーカー貼付位置を調整してください。
- **Motive の Data Streaming 設定。** `Broadcast Frame Data` を ON、**Labeled Markers** を ON、`Local Interface = 127.0.0.1`、`Transmission Type = Unicast` にしてください（Multicast の場合は `NATNET_USE_MULTICAST = True`）。
- **Windows ファイアウォール。** ループバック通信は通常ブロックされませんが、セキュリティソフトが UDP 通信を遮断している場合は、Python（`python.exe`）の通信を許可してください。
- **`NatNetClient.py` / `MoCapData.py` / `DataDescriptions.py` が読み込めるか。** これらが見つからないと import に失敗し、OptiTrack なしで続行されて座標は空欄になります。同梱の `./NatNetSDK/Samples/PythonClient/` か、本体スクリプトと同じフォルダに配置してください。

### 7.2 マーカー名と座標が入れ替わって記録される場合

- **`marker_id` と部位の対応を診断ログで確認。** 名前と座標の対応は `marker_id`（`marker_id=i` → `EXPECTED_MARKER_NAMES[i-1]`）で決まります。起動直後の診断ログで各マーカーの座標を実際の位置と突き合わせ、順序がずれていないか確認してください（例: 左右は X 座標の符号、胸は X≈0 が目印）。
- **`EXPECTED_MARKER_NAMES` を並べ替える。** ずれていた場合は、`marker_id` の並びに合わせて `EXPECTED_MARKER_NAMES` を書き換えます（CSV の位置列順もこれに追従します）。
- **余計なラベル付きマーカーが混じっていないか。** 別アセットや点群のラベル付きマーカーが `marker_id` 1〜7 と衝突する場合は、`MARKER_MODEL_ID` に対象アセットの `model_id` を指定して限定してください。

### 7.3 COM ポートが開けない / VNA に接続できない場合

［計測開始］時に **「VNAの接続に失敗しました。COM番号が正しいか、他のソフトが占有していないか確認してください」** という警告ポップアップが出る場合は、以下を確認してください（プログラムはクラッシュせず、再選択して再開できます）。

- **正しい COM ポートを選んでいるか。** GUI の各 VNA（`leftbody COM:` / `rightbody COM:`）ドロップダウンで、その台に対応するポートを選び直してください。一覧に出ない場合は VNA を接続し直し、**［ポート再検索］** ボタンで一覧を更新します。エラーログの先頭に `[leftbody]` / `[rightbody]` が付くので、どの台の失敗かを確認できます。
- **どのポートか分からないとき。** VNA を抜いて［ポート再検索］→挿して［ポート再検索］とし、増減したポートが VNA です（デバイスマネージャーの「ポート (COM と LPT)」でも確認可）。
- **他のソフトがポートを占有していないか。** **nanovna-saver や JNCRadio 純正 PC ソフト、シリアルターミナル（PuTTY 等）** が同じ COM ポートを開いていると、Python からはアクセスできません（`FileNotFoundError` / `アクセス拒否` 等）。**それらのソフトを必ず閉じてから**やり直してください。
- **VNA の電源が入っているか／ケーブルがデータ通信対応か。** 充電専用ケーブルではシリアルが認識されません。
- **ドライバ。** ポートが現れない場合は USB シリアルドライバの再インストールを検討してください。

### 7.4 S11 が全反射（≈1）になる / 13.56MHz の共振が見えない場合

`S11_Real` がほぼ 1（全反射）になる、共振の落ち込みが見えない場合は、以下を確認してください。

- **掃引範囲が共振点を含んでいるか。** `SWEEP_START_HZ`〜`SWEEP_STOP_HZ`（既定 12.5–14.5 MHz）が対象の共振点を含むか確認してください。本バージョンは初期化時に `sweep` コマンドで範囲を固定し、101 点全体を記録します（グラフで共振の落ち込みが範囲内に見えるか確認）。
- **キャリブレーション（校正）が済んでいるか。** これが S11≈1 の最も多い原因です。**未校正だと S11 はほぼ全反射になります。** 掃引範囲（12.5–14.5 MHz）を含む範囲で PORT1 の反射校正（Open / Short / Load）を実施してください（§3.2(b)）。校正範囲が掃引範囲を含まないと、補間が効かず不正確になります。
- **DUT が正しく PORT1 に接続されているか。** ケーブル断・接触不良・未接続でも全反射になります。
- **本当に整合が取れているか。** 共振点でも整合が不十分なら反射は大きくなります。NanoVNA 本体の画面（または nanovna-saver）で共振（S11 の落ち込み）が掃引範囲内に見えるか、まず単体で確認すると切り分けが容易です。

### 7.4b 2 台使用時に両方のインピーダンスに大きなノイズが乗る場合

- **交互計測が有効か確認。** 2 台を同時に掃引すると、両機が同じ帯域で同時に送信するため RF が干渉し、両方に大きなノイズが乗ります。既定の `VNA_ALTERNATE_SWEEP = True`（1 台ずつ順番に掃引）になっているか確認してください。`False`（並列同時掃引）にしているとこの干渉が起きます。
- **交互にしても残る場合。** アンテナ／コイル同士が近接して電磁結合している、同一 USB ハブでの電源・グランド結合、ケーブルの取り回し、といった物理要因も考えられます。2 台の DUT を離す、別々の USB ポート（できれば別系統）に挿す、フェライトコアを入れる、などを試してください。まず 1 台ずつ単独で計測してノイズが出ないことを確認すると切り分けが容易です。
- **FPS が下がりすぎる場合。** 交互計測では各台の FPS が同時掃引の約 1/台数になります。点数（`SCAN_POINTS`）を減らすと 1 掃引が速くなり、FPS を回復できます（周波数分解能とのトレードオフ）。

### 7.5 GUI が出ない / 2 回目の起動でフリーズする場合

- **GUI が表示されない（`ModuleNotFoundError: No module named 'tkinter'` 等）。** `tkinter` は標準ライブラリですが、最小構成の Python だと含まれないことがあります。tcl/tk 付きで Python を入れ直してください（Windows 公式インストーラは標準で同梱）。
- **2 回目以降の起動でフリーズする。** 本バージョンでは終了時に VNA・NatNet・スレッドを確実に解放するため、通常は発生しません。それでも起きる場合は、**前のプロセスが残っていないか**を確認してください（タスクマネージャーで `python.exe` / `pythonw.exe` を終了）。残存プロセスが COM ポートや UDP ポート（1510/1511）を掴んでいると、次回起動が阻害されます。
- **保存をキャンセルしたとき。** データ破棄の確認が出ます。「いいえ」を選ぶと保存ダイアログをやり直せます（蓄積済みデータはプロセス終了まで保持されます）。

### 7.5b 計測中に VNA が無応答になった / 停止・保存で固まる場合

長時間の連続計測で、nanoVNA（特に安価なクローン機）が**途中でハングして応答を返さなくなる**ことがあります。本バージョンは、この状態でも**それまでのデータを保存できる**ように次の対策を入れています。

- **無応答の自動検知とリカバリ。** 掃引データの取得に連続して失敗すると、GUI に `[VNA][警告] 掃引データを取得できません（リトライ中 …）` が表示され、内部で `pause`/`sweep` の再送によるリカバリを試みます。回復すればそのまま計測を続行します。
- **回復しない場合は自動で保存へ。** 連続失敗が続くと `VNA 応答なし` の警告を出して**計測を停止し、そのまま保存ダイアログを表示**します。**それまでに取得したサンプルはすべて保存できます**（自動では破棄されません）。
- **停止・保存が固まらない。** シリアル通信に**書き込みタイムアウト**を設定し、読み取りも停止フラグ／無応答を監視して短時間で抜けるようにしたため、デバイスがハングしても［計測終了 / 保存］やウィンドウ×が固まらずに保存まで進みます（以前は、ハングしたデバイスへの書き込みが無限にブロックして保存できませんでした）。
- **根本対策。** 機体のハングが頻発する場合は、点数（`SCAN_POINTS`）や掃引範囲を控えめにして 1 掃引を軽くする、USB ケーブル／ポートを替える、機体のファームウェアを確認する、などを検討してください。挙動を調整する定数として `SERIAL_STALL_SEC`（無応答とみなすまでの秒数）、`VNA_STALL_LOST_FAILS`（自動停止に至る連続失敗回数）があります。

### 7.6 高負荷時のデータドロップ対策（重要）

同一 PC 上で **Motive（リアルタイム 3D 描画）** と **Python 計測スクリプト**を同時に高負荷で動作させるため、CPU/GPU リソースの競合により OptiTrack のフレーム取りこぼし（ドロップ）が発生することがあります。これを防ぐための実践的なテクニックを示します。

- **計測中は Motive のウィンドウを最小化する。** Motive の 3D ビューポートの描画は GPU/CPU を大きく消費します。Data Streaming（データ配信）自体はウィンドウを最小化しても継続されるため、**計測開始後は Motive を最小化して描画負荷を下げる**ことで、ドロップを大幅に削減できます。
- **不要なアプリケーションを終了する。** ブラウザや他の重いアプリを閉じ、リソースを計測に集中させます。
- **電源プランを「高パフォーマンス」に設定する。** ThinkPad の省電力設定によるクロック低下を防ぎます。可能であれば AC 電源に接続してください。
- **Motive の描画設定を軽くする。** 描画レート（Viewport の更新頻度）やトレイル表示などを抑えると、さらに負荷を下げられます。
- **掃引点数・範囲を見直す。** `SCAN_POINTS` を大きく、`SWEEP_START_HZ`〜`SWEEP_STOP_HZ` を広くするほど 1 掃引の取得時間が延び、全体のスループット（OptiTrack との同期レート）が低下します。必要な帯域だけに範囲を狭め、点数を絞ると高速化できます（CSV 列数・グラフ点数も減ります）。

### 7.7 カメラの映像が真っ黒 / 録画動画が真っ黒な場合

ライブ表示のカメラパネルや保存された動画が**真っ黒（何も写っていない）**場合、カメラのレンズに光が入っていません。多くはハード/設定側の問題です（録画機能自体は「カメラが返した黒画像」をそのまま保存します）。計測開始時に映像が真っ黒だと判定されると、GUI が警告ダイアログを出します。次を確認してください。

- **ThinkPad の物理カメラシャッター（ThinkShutter）を開ける。** 画面上部（内蔵カメラ横）の**物理スライダー**を横にずらすとレンズが露出します。閉じていると一様な真っ黒（ノイズのみ）になります。**最も多い原因です。**
- **レンズカバー/テープ**で塞がれていないか確認する。
- **「カメラ番号」を変える。** 外部 web カメラを使う場合、内蔵カメラ（塞がれている方）ではなく外部カメラの番号を GUI の「カメラ番号」で選びます（0,1,2… と順に試す）。接続中のカメラ番号は迷ったら 0 から順に変更して確認します。
- **Windows のプライバシー設定**（設定 > プライバシーとセキュリティ > カメラ）で、デスクトップアプリのカメラアクセスが**オン**になっているか確認する。
- **他アプリがカメラを使用中**（Teams/Zoom/カメラアプリ等）だと取得できないことがあります。閉じてから計測を開始してください。
- 明るさ判定は「暗い かつ 一様（構造が無い）」ときのみ真っ黒とみなすため、**普通の暗い映像は誤検知しません**。暗いだけで内容が写っている場合は照明を足すか、カメラのオート露出が落ち着くまで少し待ってから本番計測してください（起動時に約 0.8 秒のウォームアップを入れています）。
