# OptiTrack × JNCRadio VNA 3G リアルタイム同期計測システム

メアンダコイル服（ウェアラブルアンテナ／コイル）の**3次元位置姿勢**と**高周波特性（S11・インピーダンス）**を、同一 Windows PC 上で同時かつ同期的に取得し、機械学習・解析用の CSV データセットとして保存するための Python アプリケーションです。

位置トラッキングは腕に直接貼り付けた **3 個の単一マーカー**（**上腕 / 関節 / 前腕**）を対象とします。これらは Motive 側で個別にラベル付けされた **Labeled Markers（ラベル付きマーカー）** として配信されます（Motive 3.1.0 Beta 2 以降を想定）。OptiTrack の光学式モーションキャプチャ（Motive）から得られるこの 3 マーカーの中心座標と、JNCRadio VNA 3G から得られる反射係数 S11 を、マルチスレッドかつスレッドセーフに結合し、以下の形式で記録します。

```
[Timestamp,
 UpperArm_X, UpperArm_Y, UpperArm_Z,
 Joint_X,    Joint_Y,    Joint_Z,
 Forearm_X,  Forearm_Y,  Forearm_Z,
 S11_Real, S11_Imag, Z_R, Z_X]
```

## 1. システム構成・動作環境

### 1.1 概要

本システムは、**1 台の Windows PC（ThinkPad）内で完結する**ことを最大の特徴とします。モーションキャプチャ用の PC と計測用の PC を分離せず、Motive・Python スクリプト・VNA 制御のすべてを同一マシン上で動作させることで、ネットワーク遅延や時刻同期のずれを最小化し、配線をシンプルに保ちます。

```
┌──────────────────────────────────────────────────────────────┐
│                  Windows PC (ThinkPad)                        │
│                                                              │
│   ┌────────────────┐         NatNet (UDP)                    │
│   │  Motive        │  ───────────────────────────┐           │
│   │  (OptiTrack)   │   127.0.0.1 (loopback)       │           │
│   └────────────────┘                              ▼           │
│         ▲                            ┌──────────────────────┐ │
│         │ 光学トラッキング            │  Python 同期計測       │ │
│         │                            │  スクリプト            │ │
│   （カメラ群）                        │  ・NatNetClient (受信) │ │
│                                      │  ・pyserial (VNA制御)  │ │
│   ┌────────────────┐   USB           │  ・threading.Lock      │ │
│   │ JNCRadio VNA 3G│ ◀──(COMポート)──▶│  で同期               │ │
│   │  PORT1 = S11   │   115200 bps     └──────────┬───────────┘ │
│   └────────────────┘                            │             │
│         ▲                                        ▼             │
│   （メアンダコイル服 = DUT）              sync_dataset.csv       │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 必要なハードウェア

| 機器 | 役割 | 備考 |
|------|------|------|
| **Windows PC（ThinkPad）** | Motive と Python スクリプトを同時実行する計測ホスト | 後述の通り高負荷になるため、できる限り高性能な機体を推奨 |
| **OptiTrack システム（カメラ群 + Motive）** | 腕に貼り付けた 3 個の単一マーカー（ラベル付きマーカー）の 3 次元位置をリアルタイム取得 | Motive のライセンスおよびキャリブレーション済みのキャプチャ空間が必要（Labeled Marker 配信は Motive 3.1.0 Beta 2 以降を想定） |
| **JNCRadio VNA 3G** | 単一周波数における S11（反射係数）を測定 | USB Type-C ケーブルで PC に接続。シリアル（仮想 COM ポート）として認識される |
| **メアンダコイル服（DUT）** | 被測定物 | VNA の **PORT1** に接続。上腕・関節・前腕に各 1 個、計 3 個の反射マーカーを貼付 |

### 1.3 ソフトウェア動作環境

- **OS:** Windows 10 / 11
- **Python:** 3.8 以上（64bit 推奨）
- **Motive:** OptiTrack 純正ソフトウェア（Data Streaming 対応バージョン）
- **NatNet SDK:** OptiTrack 公式 SDK（`NatNetClient.py` を使用）

## 2. セットアップ（環境構築）

### 2.1 Python ライブラリのインストール

コマンドプロンプト（または PowerShell）で以下を実行してください。

```bash
pip install pyserial pandas numpy
```

| ライブラリ | 用途 |
|-----------|------|
| `pyserial` | JNCRadio VNA 3G とのシリアル（COM ポート）通信 |
| `pandas` | 取得後のデータセットの読み込み・解析（後処理用、計測本体には任意） |
| `numpy` | 数値計算・複素数演算の補助（任意） |

> **補足:** 計測スクリプト本体の動作に必須なのは `pyserial` のみです。`pandas` / `numpy` は取得済み CSV の解析・可視化で利用するためのものです。

### 2.2 `NatNetClient.py` の配置（重要）

OptiTrack との通信には、OptiTrack が公式に配布する **NatNet SDK 同梱の Python サンプル `NatNetClient.py`** を使用します。これは `pip` では入手できません。本スクリプトは以下の **2 箇所のいずれか**に SDK ファイルがあれば自動で読み込みます（`sys.path` に自動追加）。

- **(A) 同梱 SDK をそのまま使う場合:** リポジトリ内の `./NatNetSDK/Samples/PythonClient/` に `NatNetClient.py` 等が置かれていれば、追加作業は不要です。
- **(B) 手動配置する場合:** OptiTrack 公式サイト（または Motive インストールフォルダ）から **NatNet SDK** を入手し、以下のファイルを **本体スクリプトと同じフォルダ**にコピーします。
  - `NatNetClient.py`（必須）
  - `MoCapData.py`（**必須**。Labeled Marker のデータ構造を解釈するために使用します）
  - `DataDescriptions.py`（**必須**。`NatNetClient.py` が内部で import します）

想定するフォルダ構成は以下のいずれかです。

```
# (A) 同梱 SDK 構成（このリポジトリの構成）
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── README.md
└── NatNetSDK/
    └── Samples/
        └── PythonClient/
            ├── NatNetClient.py
            ├── MoCapData.py
            └── DataDescriptions.py

# (B) 手動配置構成
nanoVNA_OptiTrack_get_dataset/
├── sync_optitrack_nanovna.py
├── NatNetClient.py
├── MoCapData.py
├── DataDescriptions.py
└── README.md
```

> **対応バージョン:** 本スクリプトは **NatNet 4.x（Motive 3.1 系）** の `NatNetClient.py` に合わせて実装しています。具体的には `new_frame_with_data_listener`（`data_dict["mocap_data"]` に `MoCapData` を渡す）を使用してラベル付きマーカー座標を取得します。Assets/Labeled Marker は Motive 3.1 / NatNet 4.1 以降でサポートされます。

## 3. 事前設定の手順

計測を開始する前に、Motive 側と JNCRadio VNA 3G 側の双方で設定を済ませておく必要があります。

### 3.1 Motive（OptiTrack）側の設定

Motive を起動し、キャプチャ空間のキャリブレーションを済ませたうえで、まず **計測対象 3 個のマーカーに正しくラベルを割り当て**、続いて **Data Streaming** パネルを設定します。

#### (a) 3 個の単一マーカーへのラベル割り当てと ID の確認【重要】

本システムは **上腕・関節・前腕に貼り付けた 3 個の単一マーカー**を、リジッドボディではなく **Labeled Marker（ラベル付きマーカー）** として識別します。Motive 側で以下を行ってください。

1. 上腕・関節・前腕のそれぞれに反射マーカーを **1 個ずつ（計 3 個）** 直接貼り付けます。
2. Motive 上で各マーカーに **ラベル（名前 / マーカー ID）を割り当てます**。
   - 例: `UpperArm`, `Joint`, `Forearm` のように、部位が分かる名前を付けます。
   - ラベル付けには、Motive のマーカーラベリング機能（手動ラベリング、または Active Marker のラベル付与など）を使用します。これにより各マーカーが安定した ID を持つ Labeled Marker として配信されます。
3. 各マーカーの **識別子（マーカー ID）** を **3 個それぞれについて控えます**。
   - この 3 つの ID を、後述のスクリプト定数 `UPPER_ARM_ID` / `JOINT_ID` / `FOREARM_ID` に正しく反映させます。
   - **ID と部位の対応を取り違えると、座標が別の部位の列に記録されてしまう**ため、必ず一つずつ確認してください。

> **ヒント（ID が分からないとき）:** スクリプト冒頭の定数 `DEBUG_PRINT_MARKER_IDS = True` に設定して実行すると、受信中の全ラベル付きマーカーの ID（`id_num` / `model` / `marker`）が 1 秒ごとにコンソールへ出力されます。1 個ずつマーカーを動かす・隠すなどして、どの ID がどの部位かを特定してから、`UPPER_ARM_ID` 等に反映させると確実です。

> **ヒント:** マーカーに安定したラベル ID が付いていないと、毎フレーム ID が変わってしまい識別できません。ラベルが固定されること（フレーム間で同じマーカーに同じ ID が割り当てられること）を必ず確認してください。

> **補足（ID の照合について）:** NatNet が配信する Labeled Marker の `id_num` は、アセットに属する場合 `(モデルID << 16) | マーカーID` の合成値になります。本スクリプトは生の `id_num` と下位 16 bit（= マーカーID）の両方で照合するため、どちらの形式でも一致を検出できます。`DEBUG_PRINT_MARKER_IDS` のログに表示される `marker=` の値を定数に設定すれば確実です。

#### (b) Data Streaming の設定

1. メニューから **Data Streaming** パネルを開きます。
2. **Broadcast Frame Data** を **ON（有効）** にします。
3. **Local Interface** を **`127.0.0.1`（localhost / loopback）** に設定します。
   - 同一 PC 内でデータを受け渡すため、外部ネットワークではなくループバックアドレスを指定するのが要点です。
4. **Transmission Type** を **Unicast** に設定します。
   - 同一 PC 内のループバック通信では Multicast よりも Unicast の方が安定します。本スクリプトも Unicast 前提（`set_use_multicast(False)`）で実装されています。
5. **Labeled Markers**（ラベル付きマーカー）のストリーミングが **ON** になっていることを確認します。
   - Data Streaming パネルに `Labeled Markers` のトグルがある場合は必ず有効化してください。これが無効だとマーカー座標が配信されません。

### 3.2 JNCRadio VNA 3G 側の設定

#### (a) COM ポート番号の確認

1. USB Type-C ケーブルで JNCRadio VNA 3G を PC に接続します。
2. **デバイスマネージャー** を開きます（`Win + X` → 「デバイス マネージャー」）。
3. **「ポート (COM と LPT)」** の項目を展開します。
4. 接続した VNA に対応する仮想シリアルポート（例: `USB Serial Device (COM3)`）を確認し、**COM 番号**を控えます。
   - 接続前後でデバイスマネージャーを見比べると、新たに増えたポートが VNA に対応するものです。
   - この COM 番号を後述の `NANOVNA_PORT` に設定します。

> JNCRadio VNA 3G のシリアルボーレートは適応式ですが、本体・スクリプトともに **115200 bps** を使用します（マニュアル §7 準拠）。

#### (b) キャリブレーション（SOLT）の事前実施【強く推奨】

S11 を正確に測定するため、**計測を開始する前に本体側で校正（キャリブレーション）を済ませておくこと**を強く推奨します。

1. メアンダコイル服を接続する **PORT1（S11 測定ポート）** に対して、付属の校正キットを用いて **SOLT 校正** を行います。
   - **S** = Short（短絡）
   - **O** = Open（開放）
   - **L** = Load（50 Ω 終端負荷）
   - **T** = Through（PORT1–PORT2 間。S11 のみであれば省略可）
2. マニュアル §4.4 / §7.2.14（`cal` コマンド）の手順に従い、各標準器を接続して校正を実施します。校正後は必ず校正データを保存（`save {id}` または本体メニュー）してください。
3. 測定したい単一周波数（例: 13.56 MHz）を含む周波数範囲で校正されていることを確認します。

> **重要:** 未校正のまま測定すると S11 が不正確になり、後段で算出されるインピーダンス Z も信頼できない値になります。データセットの品質を担保するため、校正は必ず実施してください。

## 4. 使い方（実行手順）

### 4.1 スクリプト内変数の書き換え

`sync_optitrack_nanovna.py` の冒頭にある **設定ブロック**を、ご自身の環境に合わせて編集します。

```python
# --- NanoVNA / JNCRadio VNA-3G (シリアル) ---
NANOVNA_PORT   = "COM3"        # ← デバイスマネージャーで確認した COM 番号に変更
NANOVNA_BAUD   = 115200        # ボーレート（通常は変更不要）
TARGET_FREQ_HZ = 13_560_000    # ← 測定したい単一周波数 [Hz]（例: 13.56 MHz）
SCAN_POINTS    = 11            # 1回の掃引点数（本機の最小は 11。同一周波数で平均）
Z0             = 50.0          # 特性インピーダンス [Ω]（通常は 50）

# --- OptiTrack (NatNet) ---
NATNET_SERVER_IP = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_LOCAL_IP  = "127.0.0.1"  # 同一PCなので localhost（通常は変更不要）
NATNET_USE_MULTICAST = False    # 同一PCループバックは Unicast 推奨（通常は変更不要）

# 計測する 3 個の単一マーカー（Labeled Marker）の ID（Motive の設定に合わせて変更）
UPPER_ARM_ID = 1   # ← 上腕   (Upper Arm) のマーカー ID
JOINT_ID     = 2   # ← 関節   (Joint)     のマーカー ID
FOREARM_ID   = 3   # ← 前腕   (Forearm)   のマーカー ID

# True にすると受信中の全マーカー ID を出力（ID 調査用）
DEBUG_PRINT_MARKER_IDS = False
SKIP_OCCLUDED = True            # 隠れ（オクルージョン）中のマーカーは更新をスキップ

# --- 出力 ---
OUTPUT_CSV = "sync_dataset.csv" # 出力 CSV ファイル名（任意で変更可）
```

最低限、以下を環境に合わせて変更してください。

| 変数 | 設定内容 |
|------|---------|
| `NANOVNA_PORT` | デバイスマネージャーで確認した COM 番号（例: `"COM5"`） |
| `TARGET_FREQ_HZ` | 測定対象の単一周波数（Hz 単位の整数。`13_560_000` = 13.56 MHz） |
| `UPPER_ARM_ID` | Motive で**上腕**マーカーに割り当てたラベル ID |
| `JOINT_ID` | Motive で**関節**マーカーに割り当てたラベル ID |
| `FOREARM_ID` | Motive で**前腕**マーカーに割り当てたラベル ID |

> **注意:** 3 つのマーカー ID と部位の対応関係が Motive 側と一致していることを必ず確認してください。対応を誤ると、あるマーカーの座標が別の部位の列に記録されてしまいます。ID が不明な場合は `DEBUG_PRINT_MARKER_IDS = True` で実行して確認してください。

### 4.2 実行

Motive を起動して Data Streaming を有効化し、VNA を USB 接続した状態で、以下を実行します。

```bash
python sync_optitrack_nanovna.py
```

正常に起動すると、コンソールに接続状況と計測ログが表示されます。

```
[INFO] VNA 接続 OK: COM3 @ 115200bps, 13.560 MHz
[INFO] Motive へ接続しました (server app: Motive).
[INFO] 計測対象マーカー ID -> UpperArm=1, Joint=2, Forearm=3
[INFO] OptiTrack 初期データ受信 OK(3マーカーすべて)。
[INFO] 計測開始。Ctrl+C で安全に停止します。
[   10] UA=(0.123,1.045,0.318) J=(0.181,0.812,0.301) FA=(0.254,0.553,0.288) | S11=(0.2314,-0.1502) Z=(78.21-22.13j)Ω
...
```

> ログの `UA` / `J` / `FA` はそれぞれ 上腕（UpperArm）/ 関節（Joint）/ 前腕（Forearm）の現在座標 (X, Y, Z) を示します。

### 4.3 終了方法

計測を終了するには、コンソール上で **`Ctrl + C`** を押します。

本スクリプトは `Ctrl + C` を検出すると、以下を**安全に**実行します。

1. 計測ループを停止する。
2. VNA に `resume` を送って掃引表示を元に戻し、シリアルポートを閉じる。
3. NatNet クライアントをシャットダウンする。
4. これまでに取得したサンプル数を表示する。

なお、CSV は計測中に **1 行ごとに逐次フラッシュ（`f.flush()`）して保存**しているため、万一プログラムが途中で異常終了しても、それまでのデータは失われません。

## 5. 出力データ構造（CSV ヘッダー解説）

出力ファイル（既定: `sync_dataset.csv`）は、以下の 14 カラムを持つ CSV です。位置データは **上腕・関節・前腕の 3 個の単一マーカー × (X, Y, Z) = 9 値**が含まれます。各座標は、対応する **ラベル付きマーカーの中心座標**（**Motive 3.x 標準の Z-Up 座標系**、単位はメートル）です。

> **座標系について:** 本システムは Motive で設定された配信座標系の値をそのまま記録します。Motive 3.x 標準の **Z-Up** 設定では、おおむね Z 軸が鉛直上向き、X–Y が水平面となります。解析時は Motive 側の座標系設定に合わせて軸の向きを解釈してください。

| カラム名 | 意味 | 単位 |
|----------|------|------|
| `Timestamp` | 各サンプルを記録した PC のローカル時刻（ISO 8601 形式、ミリ秒精度） | — |
| `UpperArm_X` | **上腕マーカー**の中心 X 座標（Motive 座標系） | メートル [m] |
| `UpperArm_Y` | **上腕マーカー**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `UpperArm_Z` | **上腕マーカー**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `Joint_X` | **関節マーカー**の中心 X 座標（Motive 座標系） | メートル [m] |
| `Joint_Y` | **関節マーカー**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `Joint_Z` | **関節マーカー**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `Forearm_X` | **前腕マーカー**の中心 X 座標（Motive 座標系） | メートル [m] |
| `Forearm_Y` | **前腕マーカー**の中心 Y 座標（Motive 座標系） | メートル [m] |
| `Forearm_Z` | **前腕マーカー**の中心 Z 座標（Motive 座標系） | メートル [m] |
| `S11_Real` | 反射係数 S11 の**実部** | 無次元（線形） |
| `S11_Imag` | 反射係数 S11 の**虚部** | 無次元（線形） |
| `Z_R` | 複素インピーダンス Z の**実部（抵抗 R）** | オーム [Ω] |
| `Z_X` | 複素インピーダンス Z の**虚部（リアクタンス X）** | オーム [Ω] |

> あるマーカーがトラッキングロスト等で未受信の場合、そのマーカーの X/Y/Z セルは空欄になります。上腕マーカーと前腕マーカーの位置関係から、腕の曲げ角度を後処理で算出できます。

### 5.1 同期の仕組み

OptiTrack の更新レート（数百 Hz）と VNA の取得レート（1 点あたり数十〜数百 ms）には大きな差があります。本システムでは、フレームが届くたびにコールバックが Labeled Marker のリストを走査し、計測対象 3 マーカーの座標を `threading.Lock()` 下で「マーカーごとの最新座標」として更新し続けます。そして **VNA の S11 を 1 点取得し終えた「その瞬間」に、上腕・関節・前腕 3 マーカーの最新座標を同一ロック下で一括スナップショット**して結合します。すなわち CSV の 1 行は、「ある S11 測定」と「その測定完了時点で最も新しい 3 マーカー（計 9 値）の位置データ」をまとめたものです。

ロックは 3 マーカーまとめて取得する間だけ保持されるため、読み出しの途中で一部のマーカーだけが更新される（行内でマーカーごとに時刻がずれる）ことはありません。

### 5.2 インピーダンスへの変換

CSV に記録される `Z_R`・`Z_X` は、VNA から得られた**生の S11（複素数）**を、特性インピーダンス **Z₀ = 50 Ω** を用いて以下の標準的な公式で換算したものです。

```
Z = Z0 × (1 + S11) / (1 − S11)
```

ここで、

- `S11 = S11_Real + j·S11_Imag`（反射係数、複素数）
- `Z = Z_R + j·Z_X`（負荷インピーダンス、複素数）
- `Z_R`（= R）が抵抗成分、`Z_X`（= X）がリアクタンス成分

を表します。生の S11 と換算後の Z の双方を保存しているため、後処理で別の Z₀ を用いた再計算や、S11 ベースの解析（リターンロス・VSWR 等）も柔軟に行えます。

## 6. 注意事項・トラブルシューティング

### 6.1 OptiTrack のデータが受信できない場合

コンソールに `[WARN] OptiTrack の初期データが届きません` と表示される、または座標カラムが空欄になる場合は、以下を確認してください。

- **Motive の Data Streaming が ON になっているか。** `Broadcast Frame Data` が有効である必要があります。
- **Local Interface が `127.0.0.1`（localhost）になっているか。** 別の NIC（有線/無線 LAN の IP）が選択されていると、ループバックでは受信できません。
- **Transmission Type が Unicast になっているか。** 本スクリプトは Unicast 前提です。Multicast にしている場合はスクリプト側の `set_use_multicast(True)` への変更が必要です。
- **Labeled Markers のストリーミングが ON になっているか。** Data Streaming パネルで `Labeled Markers` が無効だと、マーカー座標は配信されません。
- **Labeled Markers のストリーミングが ON か。** Data Streaming パネルで `Labeled Markers` が無効だと座標が配信されません。
- **`UPPER_ARM_ID` / `JOINT_ID` / `FOREARM_ID` が正しいか。** 3 つのマーカー ID が Motive 上のラベル ID と一致していないと、データは届いていてもフィルタで除外されます。起動時のログ `[INFO] 計測対象マーカー ID -> ...` と Motive 側の設定を突き合わせてください。一部のマーカーだけ ID が間違っていると、その列だけが空欄になります。**`DEBUG_PRINT_MARKER_IDS = True` で実行すると、受信中の全マーカー ID が出力されるので照合に便利です。**
- **マーカーのラベルが固定されているか。** マーカーに安定したラベル ID が付いておらず、フレームごとに ID が変動すると識別できません。Motive 側で各マーカーにラベルが固定的に割り当てられていることを確認してください。
- **3 個のマーカーがすべて実際にトラッキングされているか。** Motive のビューでいずれかのマーカーがロスト（オクルージョン等）していないか確認してください。起動時に `[WARN] 初期データ未受信のマーカーがあります: [...]` と表示された場合は、そのマーカーを重点的に確認します。なお `SKIP_OCCLUDED = True`（既定）では、隠れている間は座標を更新せず直前の有効値を保持します。
- **計測中に `[WARN] OptiTrack フレームが N.Ns 途絶しています` が出る場合。** Motive のストリーミングが一時停止・切断された可能性があります。Motive が前面に出ていて描画負荷が高い、PC リソース不足、または USB/ネットワークの瞬断が原因のことがあります（§6.3 参照）。
- **Windows ファイアウォール。** ループバック通信は通常ブロックされませんが、セキュリティソフトが UDP 通信を遮断している場合は、Python（`python.exe`）の通信を許可してください。
- **`NatNetClient.py` / `MoCapData.py` / `DataDescriptions.py` が読み込めるか。** これらが見つからないと import に失敗し、OptiTrack なしで続行されて座標は空欄になります。同梱の `./NatNetSDK/Samples/PythonClient/` か、本体スクリプトと同じフォルダに配置してください。

### 6.2 COM ポートが開けない場合

`[ERROR] NanoVNA シリアル接続に失敗` と表示される場合は、以下を確認してください。

- **COM 番号が正しいか。** デバイスマネージャーで再確認してください。USB を挿し直すと番号が変わることがあります。
- **他のソフトがポートを占有していないか。** **nanovna-saver や JNCRadio 純正 PC ソフト、シリアルターミナル（PuTTY 等）** が同じ COM ポートを開いていると、Python からはアクセスできません。**それらのソフトを必ず閉じてから**実行してください。
- **VNA の電源が入っているか／ケーブルがデータ通信対応か。** 充電専用ケーブルではシリアルが認識されません。
- **ドライバ。** ポートが現れない場合は USB シリアルドライバの再インストールを検討してください。

### 6.3 高負荷時のデータドロップ対策（重要）

同一 PC 上で **Motive（リアルタイム 3D 描画）** と **Python 計測スクリプト**を同時に高負荷で動作させるため、CPU/GPU リソースの競合により OptiTrack のフレーム取りこぼし（ドロップ）が発生することがあります。これを防ぐための実践的なテクニックを示します。

- **計測中は Motive のウィンドウを最小化する。** Motive の 3D ビューポートの描画は GPU/CPU を大きく消費します。Data Streaming（データ配信）自体はウィンドウを最小化しても継続されるため、**計測開始後は Motive を最小化して描画負荷を下げる**ことで、ドロップを大幅に削減できます。
- **不要なアプリケーションを終了する。** ブラウザや他の重いアプリを閉じ、リソースを計測に集中させます。
- **電源プランを「高パフォーマンス」に設定する。** ThinkPad の省電力設定によるクロック低下を防ぎます。可能であれば AC 電源に接続してください。
- **Motive の描画設定を軽くする。** 描画レート（Viewport の更新頻度）やトレイル表示などを抑えると、さらに負荷を下げられます。
- **掃引点数を見直す。** `SCAN_POINTS` を必要以上に大きくすると VNA の 1 点取得時間が延び、全体のスループットが低下します。単一周波数の平均が目的であれば、本機の最小値である `11` で十分です。
